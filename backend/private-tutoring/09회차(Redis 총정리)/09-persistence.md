# 9장. 영속성 — RDB와 AOF

> **이 장을 마치면**: Redis가 꺼졌다 켜질 때 데이터를 되살리는 두 방법(RDB, AOF)의 차이를 알고, **용도에 따라** 무엇을 고를지 정할 수 있다. Redis를 직접 강제 종료해서 확인한다.

| 주제 | 한 줄 | 중요도 |
| ---- | ----- | ------ |
| RDB | 가끔 데이터 전체를 파일로 저장 | 🟡 |
| AOF | 쓰기 명령을 할 때마다 파일에 이어 적기 | 🟡 |
| 무엇을 고르나 | 캐시면 RDB나 끔, Redis에만 있는 데이터면 AOF | 🔴 |

**실습 준비물**: [infra/persistence/](./infra/persistence) 의 `start.sh`, `crash.sh`, `stop.sh`

Spring 코드는 없다. Redis **서버 설정**의 문제다. 실무에서는 보통 인프라 담당자나 클라우드 서비스가 설정하지만, 개발자도 "내 데이터가 꺼지면 남는지"는 알아야 한다.

---

## 1. 왜 필요한가

Redis는 RAM에 저장한다(1장). 아무 설정이 없으면 꺼지는 순간 전부 사라진다.

> **영속성(Persistence)** = 메모리의 데이터를 **디스크 파일에도** 남겨서, 다시 켜질 때 되살리는 것

방법은 두 가지다.

| 방법 | 무엇을 저장하나 | 한 줄 |
| ---- | --------------- | ----- |
| **RDB** | 어느 순간의 **데이터 전체** | 사진 찍듯 가끔 통째로 저장 (스냅샷) |
| **AOF** | 실행한 **쓰기 명령** 하나하나 | `SET a 1`, `INCR b` … 명령을 계속 이어 적기 |

## 2. RDB — 가끔 통째로

데이터 전체를 `dump.rdb` 파일 하나로 저장한다. 다시 켜지면 이 파일을 읽는다.

- **자동 저장**: 기본으로 켜져 있다. "1시간에 1번 이상 바뀌면", "5분에 100번 이상 바뀌면", "1분에 1만 번 이상 바뀌면" 저장한다.
- **직접 저장**: `BGSAVE` 명령 (저장하는 동안에도 Redis는 계속 요청을 받는다).

🔴 **약점: 마지막으로 저장한 뒤에 들어온 데이터는, 갑자기 꺼지면 사라진다.** 몇 분치를 잃을 수 있다.

## 3. AOF — 명령을 계속 이어 적기

쓰기 명령을 실행할 때마다 파일 끝에 적는다. 다시 켜지면 그 명령들을 처음부터 다시 실행해서 되살린다.

파일에 적어도 운영체제가 바로 디스크에 쓰지 않고 잠깐 모아 둔다. 기본 설정(`everysec`)은 **1초마다** 디스크에 확정한다.

| 설정 (`appendfsync`) | 디스크 확정 | 갑자기 꺼지면 잃는 것 |
| -------------------- | ----------- | --------------------- |
| `always` | 명령마다 | 거의 없음 (대신 느리다) |
| **`everysec`** | 1초마다 | **약 1~2초** ← 기본값 |

파일이 계속 커지면 Redis가 알아서 "지금 상태만 남기도록" 정리한다. 신경 쓸 일은 거의 없다.

## 4. 🧪 실습 — 강제로 죽여 보기

`crash.sh`는 Redis를 **갑자기** 죽이고(정전처럼) 다시 켠다. 실습용 `redis-study`가 아니라 **임시 Redis**로 한다.

```bash
cd infra/persistence
```

### ① RDB만 (기본 설정)

**1단계. 띄우고 접속**

```bash
./start.sh rdb
docker exec -it redis-persist-test redis-cli
```

| 입력 | 결과 | 확인할 것 |
| ---- | ---- | --------- |
| `CONFIG GET appendonly` | `1) "appendonly" 2) "no"` | AOF 꺼짐 = RDB만 |
| `SET a 1` | `OK` | |
| `BGSAVE` | `Background saving started` | **여기까지** 파일에 저장 |
| `SET b 2` | `OK` | 저장 **이후** 데이터 |
| `exit` | | |

**2단계. 갑자기 죽이기**

```bash
./crash.sh
docker exec -it redis-persist-test redis-cli
```

| 입력 | 결과 | 확인할 것 |
| ---- | ---- | --------- |
| `GET a` | `"1"` | 저장한 것은 살아남았다 |
| `GET b` | `(nil)` | **저장 이후 데이터는 사라졌다** |
| `exit` | | |

### ② AOF 켜기

**1단계. AOF를 켜고 새로 띄우기**

```bash
./start.sh aof
docker exec -it redis-persist-test redis-cli
```

| 입력 | 결과 |
| ---- | ---- |
| `SET c 3` | `OK` |
| `INCR counter` | `(integer) 1` |
| `exit` | |

**2단계. 2초쯤 기다렸다가 죽이기** (1초마다 디스크에 확정되므로)

```bash
./crash.sh
docker exec -it redis-persist-test redis-cli
```

| 입력 | 결과 | 확인할 것 |
| ---- | ---- | --------- |
| `GET c` | `"3"` | 전부 살아남았다 |
| `GET counter` | `"1"` | |

### ③ 정리

```bash
./stop.sh
```

> 갑자기 죽는 게 아니라 **정상 종료**(`docker stop`)하면, RDB도 꺼지기 직전에 저장하고 꺼진다. 문제는 **갑자기** 죽을 때다.
> ⚠️ 실행 중에 `CONFIG SET appendonly yes`로 켠 설정은 **다시 켜면 사라진다.** 설정은 설정 파일이나 실행 옵션에 넣는다 (`start.sh aof`가 실행 옵션으로 켠다).

## 5. 🔴 무엇을 고를까 — 용도로 정한다

| Redis를 무엇으로 쓰나 | 설정 | 이유 |
| --------------------- | ---- | ---- |
| **캐시** (원본은 DB에 있다) | RDB만, 또는 끔 | 사라져도 DB에서 다시 채우면 된다 |
| 데이터가 **Redis에만** 있다 (로그인 세션, 랭킹) | **AOF** | 1~2초만 잃는다 |
| 절대 잃으면 안 된다 (결제, 주문) | **Redis에 원본을 두지 않는다** | DB에 둔다 |

| | RDB | AOF |
| --- | --- | --- |
| 갑자기 꺼지면 잃는 것 | 마지막 저장 이후 전부 (몇 분) | 약 1~2초 |
| 파일 크기 | 작다 | 크다 (자동으로 정리) |

> 영속성은 **같은 서버가 다시 켜질 때** 되살리는 것이다. 서버 자체가 망가지면 디스크 파일도 같이 잃는다. 그건 다른 서버에 복사본을 두는 **Replication**(10장)으로 대비한다.

## 🎯 실습 문제

**문제 1 (CLI).** 실습용 `redis-study`는 어떤 영속성 설정인가? 갑자기 꺼지면 어떻게 될까?

<details>
<summary>정답</summary>

`docker exec -it redis-study redis-cli`로 접속해서:

| 입력 | 결과 |
| ---- | ---- |
| `CONFIG GET save` | `1) "save" 2) "3600 1 300 100 60 10000"` ← RDB 자동 저장 켜짐 |
| `CONFIG GET appendonly` | `1) "appendonly" 2) "no"` ← AOF 꺼짐 |

RDB만 켜져 있다. 정상 종료하면 남지만, 갑자기 죽으면 마지막 자동 저장 이후 데이터는 사라진다. 실습용이라면 충분하다.

</details>

**문제 2 (생각).** 로그인 세션을 Redis에만 저장한다(DB에는 없음). Redis가 갑자기 재시작되면 사용자는 어떻게 되나? 어떤 설정이 맞을까?

<details>
<summary>정답</summary>

RDB만 쓰면 마지막 저장 이후 로그인한 사용자들의 세션이 사라져 **다시 로그인**해야 한다. Redis에만 있는 데이터는 AOF로 1~2초만 잃게 한다. Redis 서버 자체가 망가지는 경우에 대비해 Replica도 둔다 (10장).

</details>

## 면접 한 줄

- **RDB**: 특정 시점의 전체 데이터를 스냅샷으로 저장한다. 파일이 작고 복구가 빠르지만 마지막 저장 이후 데이터는 잃는다.
- **AOF**: 쓰기 명령을 파일에 이어 적는다. 기본(everysec)이면 1~2초만 잃는다.
- **선택 기준**: 캐시면 RDB나 끔, Redis에만 있는 데이터면 AOF, 절대 잃으면 안 되는 원본은 DB에 둔다.
