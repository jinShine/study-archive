* 스프링 DI 방법들
1. 필드 인젝션
@Autowired
private PaymentService paymentService;

2. 세터 인젝션
@Autowired
public void setPaymentService(PaymentService paymentService) {
    this.paymentService = paymentService;
}

3. 생성자 인젝션
@Autowired
public PaymentController(PaymentService paymentService) {
    this.paymentService = paymentService;
}

* @PreDestroy
Graceful shutdown 을 구현하자!

* @PreDestory 원리
1. 시스템콜
운영체제의 핵심기능들을 쓸 수 있긴 하지만
기본적으로 느리다
file(open, write, read), socket(read, write, listen), memory(alloc, free), process(fork, exit, signal), time

2. 시그널
https://sourceware.org/glibc/manual/latest/html_mono/libc.html#Termination-Signals
인텔리제이 중단버튼 누르면
종료시그널중에서 SIGINT 라는게 날아감
기존동작: 종료
kill -15 pid (SIGTERM) (SIGINT같은)

잘 만든 프로그램들은
종료시그널을 받았을때,
뒤정리를 깔끔하게해요(graceful shutdown)

절대 시그널을 핸들링할 수 없는 딱하나의 종료시그널이 있음
SIGKILL

* spring @PreDestory 는 어떻게 실행이 되고있을까?
-> 종료 시그널을 받으면 스프링이 @PreDestroy 붙은거 전부 다 호출하고 종료하게끔 시그널 핸들링이 되어있는것.
