## 1. HTML이란 무엇인가요?

**📌 핵심 정리**

1989년 팀 버너스리(Tim Berners-Lee)는 전 세계 연구자가 정보를 쉽게 공유할 수 있도록 웹을 만들었습니다. 당시에는 컴퓨터 시스템과 플랫폼마다 문서 형식이 달라 호환이 어려웠는데, 이 문제를 해결하려고 설계한 마크업 언어가 **HTML(HyperText Markup Language)** 입니다.

- **HyperText**: 문서끼리 링크(`<a>`)로 연결되는 하이퍼링크 구조
- **Markup**: 태그(`<...>`)로 콘텐츠에 "이건 제목, 이건 문단"이라고 의미를 표시하는 것
- **Language**: 약속된 태그 문법을 따르는 언어

> ⚠️ HTML은 **프로그래밍 언어가 아닙니다.** 조건·반복 같은 로직이 없고, 콘텐츠의 **구조와 의미**만 기술하는 마크업 언어입니다. (면접 단골 함정)

초기 HTML은 문서의 *구조*를 표현하는 데 집중했지만, 웹이 발전하면서 각 요소의 *의미*를 명확히 전달하는 것이 중요해졌고, 이 과정에서 **시맨틱 HTML(semantic HTML)** 개념이 등장했습니다.

**💬 책의 답변**

> HTML은 웹의 **구조**를 담당합니다. 디자인을 담당하는 CSS, 동적 기능을 담당하는 자바스크립트와 함께 현대적인 웹을 구성합니다. 특히 HTML은 각 요소의 의미와 구조를 명확히 표현하여, 검색 엔진이나 스크린 리더 같은 접근성 도구가 내용을 정확히 이해할 수 있게 합니다. 그 덕분에 웹 문서가 서로 연결되고, 더 잘 검색되며, 누구나 접근하기 쉬운 웹 환경이 만들어집니다.

**🎤 책의 모의 면접 질문**

**Q1. 웹 개발에서 HTML, CSS, 자바스크립트의 역할은 무엇인가요? 건물 짓기에 비유하면 각각 어떤 부분에 해당할까요?**

> 셋은 역할이 뚜렷이 나뉩니다. **HTML은 골조(뼈대)** — 벽·기둥·방 배치처럼 콘텐츠의 구조를 잡습니다. **CSS는 인테리어** — 벽지·색·가구 배치처럼 보기 좋게 꾸밉니다. **자바스크립트는 전기·수도 설비** — 스위치를 누르면 불이 켜지듯 동작과 상호작용을 담당합니다. 골조(HTML)가 없으면 꾸밀 대상도, 동작시킬 대상도 없으므로 HTML이 가장 기본이 됩니다.

**Q2. HTML에서 시맨틱 태그를 사용하는 이유는 무엇인가요? SEO와 웹 접근성에 어떤 도움을 주나요?**

> 시맨틱 태그는 이름 자체가 의미를 가져(`header`, `nav`, `article` 등) 문서 구조를 기계가 이해할 수 있게 합니다. **SEO** 측면에서는 검색 엔진이 어디가 제목·본문·내비게이션인지 파악해 콘텐츠 중요도를 정확히 색인합니다. **접근성** 측면에서는 스크린 리더가 "여기는 본문, 여기는 메뉴"라고 안내해 시각장애 사용자가 구조를 인지할 수 있습니다. `div`만 쓰면 이런 의미 정보가 사라져 둘 다 불리해집니다.

<details><summary>📝 한 줄 요약</summary>콘텐츠의 <b>구조와 의미</b>를 태그로 정의하는 마크업 언어(프로그래밍 언어 아님). CSS·JS와 함께 웹을 구성한다.</details>

## 2. HTML의 Doctype은 어떤 역할을 하나요?

**📌 핵심 정리**

`<!DOCTYPE>`은 문서가 어떤 HTML 버전을 따르는지 웹 브라우저에 알려 주는 **선언문**입니다. 문서 맨 위(최상단)에 위치하며, 브라우저가 어떤 규칙으로 페이지를 해석할지 결정하는 기준이 됩니다.

**Doctype의 과거와 현재**

```html
<!-- HTML4 / XHTML — DTD URL까지 길게 명시 -->
<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.01 Transitional//EN" "http://www.w3.org/TR/html4/loose.dtd">
<!DOCTYPE html PUBLIC "-//W3C//DTD XHTML 1.1//EN" "http://www.w3.org/TR/xhtml11/DTD/xhtml11.dtd">

<!-- HTML5 — 단 한 줄 -->
<!DOCTYPE html>
```

> 💡 HTML5는 특정 DTD(문서 형식 정의)에 얽매이지 않도록 설계되어, 버전 URL 없이 `<!DOCTYPE html>` 한 줄이면 충분합니다. 대소문자는 구분하지 않아 `<!doctype html>`도 유효합니다.

**💬 책의 답변**

> `<!DOCTYPE>`은 문서가 어떤 HTML 버전을 따르는지 웹 브라우저에 알려 주는 선언문입니다. 이렇게 선언하면 브라우저는 웹 사이트를 **표준 모드**로 렌더링할지, 하위 호환을 위한 **쿼크 모드**로 렌더링할지를 결정합니다.
>
> - **표준 모드(Standards Mode)**: W3C나 WHATWG 같은 웹 표준을 최대한 정확히 준수해 렌더링하는 모드로, 우리가 기대하는 방식대로 CSS와 레이아웃이 적용됩니다. HTML5의 `<!DOCTYPE html>`은 브라우저를 표준 모드로 동작하게 합니다.
> - **쿼크 모드(Quirks Mode)**: 오래전에 만들어져 현재 표준을 따르지 않는 사이트가 최신 브라우저에서도 깨져 보이지 않도록 지원하는 하위 호환 렌더링 모드입니다. Doctype이 선언되지 않거나 잘못 선언되면 브라우저는 문서가 예전 방식으로 만들어졌다고 판단해 쿼크 모드로 렌더링합니다. 이 모드에서는 CSS 해석 방식(특히 박스 모델)이 달라져 브라우저마다 결과가 다르거나 의도와 다르게 레이아웃이 구성될 수 있습니다.

**🎤 책의 모의 면접 질문**

**Q1. Doctype 선언이 웹 브라우저의 렌더링 모드에 어떤 영향을 미칠까요?**

> Doctype이 있으면 브라우저는 **표준 모드**로 진입해 최신 웹 표준대로 렌더링합니다. 반대로 Doctype이 없거나 잘못 선언되면 **쿼크 모드**로 빠져, 90년대 브라우저 호환을 위한 옛 규칙(예: 박스 모델을 `border-box`처럼 계산)으로 해석합니다. 그 결과 `width` 계산이 달라져 레이아웃이 어긋나거나 브라우저마다 결과가 달라집니다.

**Q2. 렌더링 모드에는 어떤 것이 있나요? 각각 어떤 점이 다른가요?**

> 크게 세 가지입니다. **표준 모드**는 W3C/WHATWG 표준을 그대로 따릅니다. **쿼크 모드**는 옛 브라우저 호환을 위해 비표준 방식으로 동작합니다(대표적으로 박스 모델 계산 차이). **거의 표준 모드(Almost Standards)**는 둘의 중간으로, 이미지·테이블 셀의 높이 처리 등 일부에서만 옛 방식을 따릅니다. HTML5 Doctype은 표준 모드를 보장합니다.

**Q3. HTML4/XHTML의 Doctype 선언과 HTML5의 선언은 어떤 차이가 있나요? HTML5에서 단순해진 이유는 무엇인가요?**

> HTML4/XHTML은 문서가 따르는 **DTD(문서 형식 정의)** 를 URL까지 포함해 길게 명시해야 했습니다. HTML5는 특정 DTD에 의존하지 않는 방향으로 설계되어, 버전을 식별하는 최소한의 정보(`<!DOCTYPE html>`)만으로 표준 모드를 트리거하도록 단순화됐습니다. 즉 "어떤 DTD를 검증에 쓸지"가 아니라 "표준 모드로 켜라"는 스위치 역할만 남긴 것입니다.

<details><summary>📝 한 줄 요약</summary>브라우저를 <b>표준 모드</b>로 렌더링시키는 선언. 없으면 쿼크 모드로 박스 모델·레이아웃이 깨질 수 있다. HTML5는 <code>&lt;!DOCTYPE html&gt;</code> 한 줄.</details>

## 3. `<head>` 태그 안에는 어떤 태그를 사용하나요?

**📌 핵심 정리**

`<head>`는 웹 사이트의 **설명서**입니다. 화면에는 직접 보이지 않지만, 웹 사이트의 정체성을 정의하는 **메타데이터(metadata)** 를 담는 공간입니다.

| 태그 | 역할 |
|------|------|
| `<title>` | 브라우저 탭·검색 결과·북마크에 표시되는 문서 제목 |
| `<meta>` | 문자 인코딩, 뷰포트, SEO 설명 등 다양한 메타정보 |
| `<link>` | 외부 리소스 연결 (CSS, 파비콘, 폰트 등) |
| `<style>` | 문서 내부에 직접 작성하는 CSS |
| `<script>` | 자바스크립트 연결·삽입 (보통 `defer`/`async` 사용) |

**`<meta>` 태그 자세히 — 하나의 태그, 여러 얼굴**

```html
<meta charset="UTF-8" />                                <!-- 문자 인코딩(한글 깨짐 방지). head 최상단 권장 -->
<meta name="viewport" content="width=device-width, initial-scale=1.0" /> <!-- 반응형의 핵심 -->
<meta name="description" content="페이지 요약" />         <!-- 검색 결과에 뜨는 설명문(SEO) -->
<meta name="robots" content="index, follow" />          <!-- 검색 엔진 크롤링·색인 제어 -->
<meta property="og:title" content="공유 제목" />          <!-- 오픈그래프: 카톡·페북 공유 미리보기 -->
```

- `charset`: 문서의 문자 인코딩 지정. **head 앞쪽 1024바이트 안**에 와야 브라우저가 올바르게 해석합니다.
- `viewport`: 없으면 모바일에서 데스크톱 너비로 축소 렌더링돼 반응형 미디어 쿼리가 의도대로 동작하지 않습니다.
- `description` / `og:*`: 검색·SNS 공유 시 노출되는 정보로 클릭률(UX)과 SEO에 직접 영향.

**`<link>` 태그 자세히 — 외부 리소스 연결의 관문**

```html
<link rel="stylesheet" href="style.css" />              <!-- CSS 연결 -->
<link rel="icon" href="/favicon.ico" />                 <!-- 파비콘 -->
<link rel="canonical" href="https://example.com/page" /><!-- 중복 URL 정리(SEO) -->
<link rel="preconnect" href="https://fonts.gstatic.com" /> <!-- 성능: 미리 연결 -->
<link rel="preload" href="/hero.webp" as="image" />     <!-- 성능: 중요한 리소스 미리 로드 -->
```

- `rel` 속성으로 "이 링크가 어떤 관계의 리소스인지"를 지정하는 것이 핵심입니다.
- `preconnect`, `preload`, `dns-prefetch`는 **성능 최적화**용, `canonical`은 **SEO**용(중복 콘텐츠 방지).

**💬 책의 답변**

> `<head>` 태그는 웹 사이트의 메타데이터를 담아, 웹 브라우저와 검색 엔진에 페이지의 성격과 동작 방식을 알려 주는 역할을 합니다. 겉으로는 보이지 않지만 **성능 최적화, 검색 엔진 최적화(SEO), 크로스 플랫폼 호환성** 확보에 매우 중요합니다.

**🎤 책의 모의 면접 질문**

**Q1. `<head>` 태그의 설정은 검색 엔진 최적화와 사용자 경험(UX)에 왜 중요한 영향을 미치나요?**

> `<head>`에는 검색 엔진이 페이지를 이해하는 데 쓰는 핵심 정보가 모여 있기 때문입니다. **SEO** 측면에서는 `<title>`과 `<meta name="description">`이 검색 결과에 그대로 노출되고, `canonical`·`robots`가 색인 방식을 결정합니다. **UX** 측면에서는 `viewport`가 모바일 반응형을 좌우하고, `<meta charset>`이 한글 깨짐을 막으며, `preload`/`preconnect` 같은 리소스 힌트가 초기 로딩 속도를 개선합니다. 즉 `<head>` 설정이 "검색에 잘 걸리는가"와 "빠르고 올바르게 보이는가"를 동시에 결정합니다.

<details><summary>📝 한 줄 요약</summary>화면에 안 보이는 <b>메타데이터</b> 영역: <code>title</code>·<code>meta</code>·<code>link</code>·<code>style</code>·<code>script</code>. 성능·SEO·호환성의 핵심.</details>

## 4. 시맨틱 태그란 무엇이고, 사용하는 이유를 설명할 수 있나요?

**📌 핵심 정리**

시맨틱(semantic) 태그는 **이름 자체로 콘텐츠의 의미와 역할을 전달하는** HTML 태그입니다. 의미 없는 `<div>` 대신 사용하면 사람과 기계 모두 문서 구조를 명확히 이해할 수 있습니다.

**주요 시맨틱 태그**

| 태그 | 의미·역할 |
|------|----------|
| `<header>` | 페이지·섹션의 머리말 (로고, 제목, 주요 내비게이션) |
| `<nav>` | 주요 내비게이션 링크 모음 |
| `<main>` | 문서의 핵심 본문 (페이지당 1개) |
| `<article>` | 그 자체로 독립·재사용 가능한 콘텐츠 (블로그 글, 뉴스 기사) |
| `<section>` | 주제별로 묶는 일반 구획 (보통 제목 포함) |
| `<aside>` | 본문과 간접적으로 연관된 부가 정보 (사이드바, 광고) |
| `<footer>` | 페이지·섹션의 꼬리말 (저작권, 연락처, 링크) |

> 🎯 `<section>` vs `<article>`: `article`은 떼어내도 독립적으로 성립하는 콘텐츠, `section`은 주제별로 묶는 구획입니다.

**사용하는 이유 (3가지)**

1. **검색 엔진 최적화(SEO)**: 검색 엔진이 콘텐츠 구조·중요도를 정확히 파악
2. **웹 접근성 향상**: 스크린 리더가 영역(본문/메뉴/부가정보)을 인식해 사용자에게 안내
3. **코드 가독성·유지보수 효율 향상**: 코드만 봐도 구조가 읽혀 협업이 쉬움

**💬 책의 답변**

> 시맨틱 태그는 콘텐츠의 의미를 명확히 전달하는 HTML 태그입니다. 단순히 영역만 구분하는 `<div>`와 달리 `<header>`, `<main>`, `<article>` 같은 태그는 웹 페이지의 구조와 역할을 설명합니다. 이 덕분에 브라우저와 검색 엔진이 페이지를 더 정확히 이해할 수 있습니다. 그 결과 검색 엔진 최적화가 향상되고, 스크린 리더가 구조를 쉽게 인식해 웹 접근성도 크게 개선됩니다. 또한 코드의 가독성과 유지보수성이 높아져 개발자에게도 효율적인 개발 환경을 제공합니다.

**🎤 책의 모의 면접 질문**

**Q1. `<header>`, `<main>`, `<article>` 같은 시맨틱 태그를 사용하면 SEO와 웹 접근성에 어떤 이점이 있을까요?**

> 시맨틱 태그는 각 영역의 역할을 기계가 읽을 수 있게 명시합니다. **SEO**에서는 검색 엔진이 `<main>`을 핵심 본문으로, `<article>`을 독립 콘텐츠로 인식해 색인 품질과 검색 노출이 좋아집니다. **접근성**에서는 스크린 리더가 랜드마크(landmark)로 인식해 "본문으로 건너뛰기", "내비게이션으로 이동" 같은 탐색을 지원하므로, 시각장애 사용자가 페이지를 훨씬 효율적으로 이용할 수 있습니다.

**Q2. `<div>` 대신 시맨틱 태그를 쓰는 것이 코드 가독성·유지보수성 측면에서 왜 더 유리할까요?**

> `<div class="header">`처럼 클래스명에 의존하면 그 의미를 코드 작성자만 알 수 있고, 클래스명이 바뀌면 의도가 사라집니다. 반면 `<header>`는 태그 이름 자체가 역할을 말해 주므로, 처음 코드를 보는 사람도 구조를 즉시 파악합니다. 결과적으로 협업·리뷰·유지보수가 쉬워지고, `div` 남발("div 수프")로 인한 구조 파악의 어려움을 줄일 수 있습니다.

<details><summary>📝 한 줄 요약</summary>이름에 <b>의미</b>가 담긴 태그. SEO·접근성·유지보수성을 위해 <code>div</code> 대신 사용한다.</details>

## 5. 웹 표준과 웹 접근성이란 무엇인가요?

**📌 핵심 정리**

**웹 표준(Web Standards)** 은 W3C 같은 공식 표준화 기구가 제정한 웹 기술의 공식 규약입니다. 쉽게 말해 웹 사이트를 만들 때 따라야 할 공통 규칙을 전 세계가 합의한 것으로, **웹의 헌법**이라 할 수 있습니다. 이런 규칙이 필요한 이유는 **크로스 브라우징(Cross-Browsing)** — 어떤 브라우저·환경에서도 동일하게 동작하게 하기 위해서입니다.

**웹 접근성(Web Accessibility)** 은 사용자의 장애 여부나 이용 환경에 관계없이 누구나 웹 콘텐츠를 똑같이 인식하고 사용할 수 있도록 보장하는 원칙입니다.

> 🎯 표준 = "브라우저가 다 알아듣게" / 접근성 = "사람이 다 쓸 수 있게". 서로 다른 목적이지만 시맨틱 마크업이라는 지점에서 만납니다.

**💬 책의 답변**

> - **웹 표준**은 브라우저와 환경에 상관없이 동일하게 동작하는 웹을 만들기 위한 공식 규약입니다. 호환성, 유지보수성, 검색 엔진 최적화에 이점을 제공합니다.
> - **웹 접근성**은 장애 유무나 환경에 관계없이 모든 사용자가 동등하게 웹을 이용할 수 있도록 보장하는 철학으로, 대체 텍스트 제공, 키보드 접근성, 색상 대비 확보 등이 핵심 요소입니다.

**🎤 책의 모의 면접 질문**

**Q1. 웹 표준과 웹 접근성의 차이점과 각각의 목적은 무엇인가요?**

> **웹 표준**은 *기계(브라우저)* 를 향한 규칙으로, 어떤 환경에서도 웹이 일관되게 동작하도록(크로스 브라우징) 보장하는 것이 목적입니다. **웹 접근성**은 *사람(사용자)* 을 향한 원칙으로, 장애 여부나 환경과 무관하게 누구나 동등하게 콘텐츠를 이용하도록 보장하는 것이 목적입니다. 대상과 목적은 다르지만, 표준을 잘 지킨 시맨틱 마크업이 접근성의 기반이 되므로 둘은 밀접히 연결됩니다.

**Q2. 웹 접근성을 높이기 위해 HTML에서 적용할 수 있는 구체적인 방법 3가지는 무엇인가요?**

> ① **대체 텍스트**: `<img>`에 `alt` 속성을 제공해 스크린 리더가 이미지를 설명할 수 있게 합니다. ② **시맨틱 마크업**: `<header>`·`<nav>`·`<main>` 등 랜드마크 태그와 올바른 헤딩 구조(`<h1>`~`<h6>`)로 탐색을 돕습니다. ③ **폼 레이블 연결**: `<label for="...">`로 입력 요소와 설명을 연결하고, 필요 시 `aria-*` 속성으로 상태를 보완합니다. (추가로 키보드 포커스 순서·색상 대비 확보도 중요합니다.)

<details><summary>📝 한 줄 요약</summary>웹 표준 = 브라우저 간 일관 동작을 위한 <b>공식 규약</b>. 웹 접근성 = 누구나 동등하게 쓰도록 보장하는 <b>원칙</b>(alt·시맨틱·레이블).</details>

## 6. 모든 HTML 태그에는 종료 태그가 있나요?

**📌 핵심 정리**

아닙니다. HTML 태그는 **일반 태그**와 **빈 태그(void element)** 로 나뉩니다.

- **일반 태그**: 여는 태그 + 콘텐츠 + 닫는 태그 (`<p>...</p>`, `<div>...</div>`)
- **빈 태그**: 내부 콘텐츠를 가질 수 없어 닫는 태그가 없음 (`<img>`, `<br>`, `<hr>`, `<input>`, `<meta>`, `<link>`)

빈 태그는 그 자체로 완결된 요소라 콘텐츠를 담을 수 없고, 따라서 종료 태그가 필요 없습니다.

**💬 책의 답변**

> HTML의 모든 태그가 종료 태그를 가지는 것은 아닙니다. `<img>`, `<br>`, `<hr>` 등과 같은 **빈 태그**는 그 자체로 완결된 요소로, 내부 콘텐츠를 가질 수 없습니다. HTML5에서는 이러한 빈 태그를 간결하게 작성하며, 파서는 태그 이름만으로 빈 태그임을 인식해 종료 태그를 기다리지 않고 즉시 DOM에 추가합니다. 또한 XHTML 스타일로 슬래시(`/`)를 붙이는 방식은 무시되며, 빈 태그는 자체로 완전한 단위로 처리되어 브라우저에 바로 렌더링됩니다.

**🎤 책의 모의 면접 질문**

**Q1. HTML에서 빈 태그와 일반 태그는 구조적으로 어떤 차이가 있나요? 왜 빈 태그에는 종료 태그가 필요하지 않나요?**

> 일반 태그는 여는 태그와 닫는 태그 사이에 **자식 콘텐츠**를 담을 수 있는 컨테이너입니다(`<p>텍스트</p>`). 반면 빈 태그는 콘텐츠를 담는 그릇이 아니라 그 자체로 하나의 완결된 요소입니다. 예를 들어 `<img>`는 이미지 자체, `<br>`은 줄바꿈 하나를 의미할 뿐 내부에 넣을 내용이 없습니다. 담을 콘텐츠가 없으니 "어디서 끝나는지" 알려 줄 종료 태그도 필요 없는 것입니다.

**Q2. HTML5 파서는 `<img>`, `<br>` 같은 빈 태그를 어떻게 처리하나요? XHTML 스타일의 슬래시(`/`)는 어떤 영향을 미치나요?**

> HTML5 파서는 빈 태그를 **태그 이름만으로** 식별합니다. 미리 정해진 void element 목록에 속하므로, 파서는 종료 태그를 기다리지 않고 곧바로 DOM에 노드를 추가합니다. `<img />`처럼 XHTML 스타일의 슬래시를 붙여도 HTML5에서는 **무시**되어 `<img>`와 동일하게 처리됩니다. 즉 슬래시 유무는 렌더링 결과에 아무 영향이 없습니다(JSX 등에서는 문법상 필요할 수 있지만 순수 HTML5 파싱에는 무관).

<details><summary>📝 한 줄 요약</summary>빈 태그(<code>img</code>·<code>br</code>·<code>hr</code> 등)는 콘텐츠가 없어 <b>종료 태그가 불필요</b>. HTML5에서 <code>/</code>는 무시된다.</details>
