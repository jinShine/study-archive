## Q1. HTML이란 무엇인가요? 🔴

**💬 30초 답변**
> HTML(HyperText Markup Language)은 웹 페이지의 **구조와 의미를 정의하는 마크업 언어**입니다. 프로그래밍 언어가 아니라, 태그로 "이건 제목, 이건 문단, 이건 이미지"라고 콘텐츠의 역할을 브라우저에 알려주는 역할을 합니다.

**📖 핵심 개념**

🎯 **비유**: HTML은 집의 **골조(뼈대)** 입니다. CSS는 인테리어(꾸미기), JavaScript는 전기·수도 같은 동작(기능)이라고 보면 됩니다. 골조 없이는 꾸밀 대상도, 동작시킬 대상도 없습니다.

📌 **정의**
- **HyperText**: 문서끼리 링크(`<a>`)로 연결되는 하이퍼링크 구조
- **Markup**: 태그(`<...>`)로 콘텐츠에 의미를 "표시(mark up)"하는 것
- **Language**: 약속된 문법(태그 규칙)을 따르는 언어

❌ HTML을 "프로그래밍 언어"라고 답하면 감점 — 조건·반복 같은 로직이 없으므로 마크업 언어입니다.
✅ "콘텐츠의 구조와 의미를 기술하는 마크업 언어"가 정확한 표현.

**💻 예시**
```html
<!DOCTYPE html>
<html lang="ko">
  <head>
    <meta charset="UTF-8" />
    <title>문서 제목</title>
  </head>
  <body>
    <h1>제목</h1>
    <p>문단입니다.</p>
  </body>
</html>
```

**🔥 예상 꼬리질문**
- Q. HTML은 프로그래밍 언어인가요? → A. 아닙니다. 로직(연산·제어)이 없는 마크업 언어입니다.
- Q. HTML5에서 새로 생긴 것은? → A. 시맨틱 태그(`header`, `nav`, `article` 등), `<canvas>`, `<video>`/`<audio>`, 웹 스토리지, `<input>` 타입 확장 등.

<details><summary>📝 한 줄 요약</summary>콘텐츠의 <b>구조와 의미</b>를 태그로 정의하는 마크업 언어. 프로그래밍 언어가 아니다.</details>

## Q2. HTML의 Doctype은 어떤 역할을 하나요? 🟡

**💬 30초 답변**
> `<!DOCTYPE html>`은 문서의 HTML 버전을 브라우저에 알려, **표준 모드(standards mode)** 로 렌더링하게 하는 선언입니다. 생략하거나 잘못 쓰면 브라우저가 **쿼크 모드(quirks mode)** 로 동작해 박스 모델 등이 옛날 방식으로 깨질 수 있습니다.

**📖 핵심 개념**

🎯 **비유**: 문서 맨 위에 붙이는 "이 문서는 최신 규격을 따릅니다"라는 **선언문**입니다. 이 선언이 없으면 브라우저가 "옛날 호환 모드로 봐야 하나?" 하고 다르게 해석합니다.

📌 **렌더링 모드 3가지**
- **표준 모드(Standards)**: 최신 W3C 표준대로 렌더링 (우리가 원하는 것)
- **쿼크 모드(Quirks)**: 90년대 브라우저 호환을 위한 옛 동작 (박스 모델이 `content-box`가 아닌 옛 방식 등)
- **거의 표준 모드(Almost Standards)**: 둘의 중간

```
❌ Doctype 없음 → 쿼크 모드 → width 계산이 padding/border 포함하는 옛 방식
✅ <!DOCTYPE html> → 표준 모드 → 일관된 박스 모델
```

> 💡 HTML5의 Doctype은 `<!DOCTYPE html>` 단 한 줄로 간단합니다. HTML4는 DTD URL까지 길게 적었지만 지금은 쓰지 않습니다.

**🔥 예상 꼬리질문**
- Q. 대소문자를 구분하나요? → A. 구분하지 않습니다. `<!doctype html>`도 유효합니다.
- Q. 쿼크 모드의 대표적 문제는? → A. 박스 모델 계산 방식이 달라 레이아웃이 어긋나고, 일부 CSS가 무시됩니다.

<details><summary>📝 한 줄 요약</summary>브라우저를 <b>표준 모드</b>로 렌더링시키는 선언. 없으면 쿼크 모드로 레이아웃이 깨질 수 있다.</details>

## Q3. `<head>` 태그 안에는 어떤 태그를 사용하나요? 🟡

**💬 30초 답변**
> `<head>`는 화면에 직접 보이지 않는 **문서의 메타데이터**를 담는 영역입니다. 문자 인코딩, 제목, 뷰포트 설정, CSS/스크립트 연결, SEO·소셜 공유용 메타 태그 등이 들어갑니다.

**📖 핵심 개념**

📌 **주요 태그**

| 태그 | 역할 |
|------|------|
| `<meta charset="UTF-8">` | 문자 인코딩 지정 (한글 깨짐 방지, **head 최상단** 권장) |
| `<title>` | 브라우저 탭·검색 결과에 뜨는 문서 제목 |
| `<meta name="viewport">` | 반응형의 핵심 — 모바일 뷰포트 설정 |
| `<meta name="description">` | 검색 결과 요약문 (SEO) |
| `<link rel="stylesheet">` | 외부 CSS 연결 |
| `<link rel="icon">` | 파비콘 |
| `<script>` | JS 연결 (보통 `defer`/`async` 또는 body 끝) |
| `<meta property="og:*">` | 오픈그래프 — 카톡·페북 공유 미리보기 |

```html
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>My Page</title>
  <meta name="description" content="페이지 설명" />
  <link rel="stylesheet" href="style.css" />
</head>
```

> 💡 `charset`은 head 안에서도 **맨 앞 1024바이트 안**에 와야 브라우저가 올바르게 해석합니다.

**🔥 예상 꼬리질문**
- Q. viewport 메타 태그가 왜 중요한가요? → A. 없으면 모바일에서 데스크톱 너비로 축소 렌더링되어 반응형 미디어 쿼리가 의도대로 동작하지 않습니다.
- Q. `<head>`의 내용은 화면에 보이나요? → A. `<title>` 정도가 탭에 보이고, 대부분 메타데이터라 본문에는 안 보입니다.

<details><summary>📝 한 줄 요약</summary>화면에 안 보이는 <b>메타데이터</b> 영역: charset, title, viewport, CSS/JS 연결, SEO·OG 태그.</details>

## Q4. 시맨틱 태그란 무엇이고, 사용하는 이유를 설명할 수 있나요? 🔴

**💬 30초 답변**
> 시맨틱(semantic) 태그는 `header`, `nav`, `main`, `article`, `section`, `footer`처럼 **이름 자체가 의미를 가지는 태그**입니다. `div`처럼 의미 없는 박스 대신 사용하면, 검색엔진·스크린리더·개발자가 문서 구조를 명확히 이해할 수 있습니다.

**📖 핵심 개념**

🎯 **비유**: 시맨틱 태그는 서류 봉투에 "계약서", "영수증"이라고 **라벨을 붙이는 것**입니다. `div`만 쓰는 건 모든 봉투에 라벨 없이 똑같이 쌓아두는 것 — 사람(개발자)도, 기계(검색엔진·스크린리더)도 안을 일일이 열어봐야 압니다.

❌ **비시맨틱 (의미 없음)**
```html
<div class="header">
  <div class="nav">...</div>
</div>
<div class="main">
  <div class="article">...</div>
</div>
```
✅ **시맨틱 (의미 명확)**
```html
<header>
  <nav>...</nav>
</header>
<main>
  <article>...</article>
</main>
```

📌 **사용 이유 (면접 핵심 3가지)**
1. **접근성(a11y)**: 스크린리더가 "여기는 내비게이션, 여기는 본문"을 인식해 시각장애 사용자에게 구조를 전달
2. **SEO**: 검색엔진이 콘텐츠 구조·중요도를 파악하기 쉬움
3. **유지보수성**: 코드만 봐도 구조가 읽혀 협업·가독성 향상

**🔥 예상 꼬리질문**
- Q. `<section>`과 `<article>`의 차이는? → A. `article`은 그 자체로 독립적으로 배포·재사용 가능한 콘텐츠(블로그 글, 뉴스 기사). `section`은 주제별로 묶는 일반 구획.
- Q. `<div>`는 이제 쓰면 안 되나요? → A. 아닙니다. 의미가 없는 순수 스타일링·레이아웃 그룹핑에는 여전히 `div`가 적절합니다.

<details><summary>📝 한 줄 요약</summary>이름에 <b>의미</b>가 담긴 태그. 접근성·SEO·유지보수성을 위해 div 대신 사용한다.</details>

## Q5. 웹 표준과 웹 접근성이란 무엇인가요? 🔴

**💬 30초 답변**
> **웹 표준(Web Standards)** 은 W3C 등이 정한 규격을 따라 어떤 브라우저·기기에서도 동일하게 동작하게 만드는 것이고, **웹 접근성(Web Accessibility, a11y)** 은 장애인·고령자를 포함한 모든 사용자가 콘텐츠를 이용할 수 있도록 만드는 것입니다.

**📖 핵심 개념**

📌 **웹 표준**
- HTML/CSS/JS를 표준 규격대로 작성 → **크로스 브라우징**(브라우저 호환성) 확보
- 시맨틱 마크업, 유효한 문법 사용
- "한 번 작성하면 어디서나 동작"을 지향

📌 **웹 접근성 (a11y)**
- `a11y` = **a** + (11글자) + **y** (Accessibility의 줄임)
- 기준: **WCAG**(Web Content Accessibility Guidelines), 국내는 **KWCAG**
- 구체적 실천:
  - 이미지에 `alt` 속성 (스크린리더가 읽음)
  - 폼 `<label>`과 input 연결
  - 키보드만으로 모든 기능 사용 가능(`tabindex`, 포커스 관리)
  - 충분한 색 대비, 시맨틱 태그, `aria-*` 속성

```html
<!-- ❌ 접근성 나쁨 -->
<div onclick="submit()">전송</div>
<img src="logo.png" />

<!-- ✅ 접근성 좋음 -->
<button onclick="submit()">전송</button>
<img src="logo.png" alt="회사 로고" />
```

> 💡 `<div onclick>`은 키보드 포커스·엔터 동작이 안 됩니다. 클릭 동작은 `<button>`을 써야 접근성과 시맨틱을 동시에 만족합니다.

**🔥 예상 꼬리질문**
- Q. 둘의 관계는? → A. 웹 표준을 잘 지키면(시맨틱·유효한 마크업) 접근성도 자연히 좋아집니다. 접근성은 표준의 중요한 목표 중 하나입니다.
- Q. ARIA란? → A. Accessible Rich Internet Applications. 시맨틱만으로 부족할 때 `role`, `aria-label` 등으로 보조기술에 의미를 보강하는 명세입니다. 단, **네이티브 태그(`button` 등)로 해결되면 ARIA보다 그게 우선**입니다.

<details><summary>📝 한 줄 요약</summary>웹 표준 = 규격 준수로 모든 브라우저 호환 / 웹 접근성 = 장애인 포함 모든 사용자가 이용 가능하게.</details>

## Q6. 모든 HTML 태그에는 종료 태그가 있나요? 🟢

**💬 30초 답변**
> 아닙니다. 내용을 가질 수 없는 **빈 요소(void element)** 는 종료 태그가 없습니다. `<img>`, `<br>`, `<hr>`, `<input>`, `<meta>`, `<link>` 등이 대표적입니다.

**📖 핵심 개념**

📌 **빈 요소(void element)**: 자식 콘텐츠를 가질 수 없는 태그. 닫는 태그(`</img>`)가 존재하지 않습니다.

| 빈 요소 | 용도 |
|---------|------|
| `<img>` | 이미지 |
| `<br>` | 줄바꿈 |
| `<hr>` | 수평선 |
| `<input>` | 입력 필드 |
| `<meta>` | 메타데이터 |
| `<link>` | 외부 리소스 연결 |

```html
<!-- HTML5: 닫는 슬래시 선택 -->
<img src="a.png" alt="">
<br>

<!-- XHTML/JSX: 자체 닫기(self-closing) 필요 -->
<img src="a.png" alt="" />
<br />
```

> 💡 HTML5에서는 `<br>`, `<br/>` 둘 다 유효합니다. 하지만 **JSX/XHTML에서는 반드시 `/`로 닫아야** 합니다(`<br />`). React를 쓴다면 self-closing이 필수라는 점을 같이 언급하면 좋습니다.

**🔥 예상 꼬리질문**
- Q. `<p>`의 닫는 태그를 생략할 수 있나요? → A. HTML 파서가 자동 보정하는 경우가 있지만(예: 다음 블록 요소 시작 시), 명시적으로 닫는 것이 안전하고 가독성에 좋습니다.

<details><summary>📝 한 줄 요약</summary>빈 요소(void element: img, br, hr, input, meta, link)는 종료 태그가 없다. JSX에선 self-closing 필수.</details>

## Q7. 블록 요소와 인라인 요소란 무엇인가요? 🔴

**💬 30초 답변**
> **블록 요소**는 한 줄을 통째로 차지하며 위아래로 쌓이고 `width`/`height`/상하 `margin`이 적용됩니다(`div`, `p`, `h1`, `section`). **인라인 요소**는 콘텐츠 크기만큼만 차지하고 옆으로 나열되며 `width`/`height`와 상하 margin이 적용되지 않습니다(`span`, `a`, `strong`).

**📖 핵심 개념**

```
[ 블록 요소 ]  ← 한 줄 전체 차지, 다음 요소는 아래로
████████████████████████████
[블록]
████████████████████████████

[ 인라인 요소 ]  ← 콘텐츠만큼만, 옆으로 나란히
[인라인][인라인][인라인] →
```

📌 **비교표**

| 구분 | 블록(block) | 인라인(inline) |
|------|-------------|----------------|
| 줄 차지 | 한 줄 전체 | 콘텐츠 크기만 |
| 배치 | 세로로 쌓임 | 가로로 나열 |
| width/height | 적용됨 | **무시됨** |
| margin/padding | 상하좌우 모두 | 좌우만 정상, **상하는 레이아웃에 영향 X** |
| 예시 | `div p h1~h6 ul li section` | `span a strong em img` |

> 💡 **inline-block**: 인라인처럼 옆으로 나열되면서 width/height/상하 margin도 먹는 중간 형태. 버튼·메뉴 아이템에 자주 씁니다.

```css
.tag { display: inline-block; width: 80px; height: 30px; }
```

**🔥 예상 꼬리질문**
- Q. 인라인 요소에 width가 안 먹는데 크기를 주려면? → A. `display: inline-block` 또는 `block`으로 변경, 혹은 flex/grid 아이템으로 만듭니다.
- Q. `<a>`는 인라인인데 영역 전체를 클릭 영역으로 만들려면? → A. `display: block`(또는 inline-block) 후 width/height/padding 지정.

<details><summary>📝 한 줄 요약</summary>블록 = 한 줄 차지·width/height 적용(div,p,h1) / 인라인 = 콘텐츠만큼·width 무시(span,a). 중간은 inline-block.</details>

## Q8. `data-*` 속성을 설명할 수 있나요? 🟡

**💬 30초 답변**
> `data-*`는 HTML 요소에 **커스텀 데이터를 저장**하는 표준 속성입니다. `data-` 접두사를 붙이면 어떤 이름이든 만들 수 있고, JavaScript의 `element.dataset`으로 접근합니다. DOM에 의미 있는 데이터를 심을 때 사용합니다.

**📖 핵심 개념**

```html
<button data-user-id="42" data-role="admin">프로필</button>
```
```js
const btn = document.querySelector('button');
btn.dataset.userId;  // "42"  (data-user-id → userId, 카멜케이스 변환)
btn.dataset.role;    // "admin"
btn.dataset.userId = "99";  // 값 변경
```

📌 **특징**
- 이름은 `data-` + 소문자/하이픈 (`data-user-id`)
- JS에서는 **카멜케이스**로 변환되어 `dataset.userId`로 접근
- 값은 항상 **문자열**
- CSS에서도 `[data-role="admin"]` 속성 선택자로 활용 가능

🎯 **언제 쓰나**: 서버 id를 DOM에 심어두고 클릭 시 읽기, 탭 상태 표시(`data-active`), 테스트 셀렉터(`data-testid`) 등.

```css
button[data-role="admin"] { border: 2px solid gold; }
```

**🔥 예상 꼬리질문**
- Q. `id`/`class`에 데이터를 넣는 것과 뭐가 다른가요? → A. id/class는 식별·스타일링용이고, `data-*`는 의미적 데이터 저장 전용이라 역할이 명확히 분리됩니다.
- Q. 민감한 정보를 넣어도 되나요? → A. 안 됩니다. HTML 소스에 그대로 노출되므로 토큰·비밀번호 등은 금지.

<details><summary>📝 한 줄 요약</summary>요소에 커스텀 데이터를 심는 표준 속성. JS는 <code>dataset</code>(카멜케이스)로, CSS는 속성 선택자로 접근. 값은 문자열.</details>

## Q9. 웹 스토리지란 무엇인가요? 🔴

**💬 30초 답변**
> 웹 스토리지는 브라우저에 데이터를 키-값 형태로 저장하는 API로, **localStorage**(영구 저장)와 **sessionStorage**(탭 닫으면 삭제) 두 가지가 있습니다. 쿠키와 달리 **서버로 자동 전송되지 않고 용량이 크며(약 5~10MB)** 순수 클라이언트 저장 용도입니다.

**📖 핵심 개념**

📌 **3가지 비교 (면접 빈출!)**

| 구분 | localStorage | sessionStorage | cookie |
|------|--------------|----------------|--------|
| 수명 | 영구 (직접 지워야 삭제) | 탭/창 닫으면 삭제 | 만료일 지정 |
| 용량 | ~5–10MB | ~5–10MB | ~4KB |
| 서버 전송 | ❌ 안 됨 | ❌ 안 됨 | ✅ 매 요청 자동 전송 |
| 접근 | JS만 | JS만 | JS + 서버 (`HttpOnly`면 서버만) |
| 범위 | 같은 origin 공유 | 탭별로 격리 | 도메인/경로 |

```js
localStorage.setItem('theme', 'dark');
localStorage.getItem('theme');     // "dark"
localStorage.removeItem('theme');
localStorage.clear();

// 객체는 직렬화 필요
localStorage.setItem('user', JSON.stringify({ id: 1 }));
JSON.parse(localStorage.getItem('user'));
```

🎯 **언제 무엇을?**
- **localStorage**: 다크모드 설정, 장바구니 임시 저장 등 오래 유지할 비민감 데이터
- **sessionStorage**: 탭 단위 일회성 상태(다단계 폼 진행값 등)
- **cookie**: 서버가 알아야 하는 인증 토큰(특히 `HttpOnly`+`Secure`로 XSS 방어)

> ⚠️ 웹 스토리지는 JS로 접근 가능하므로 **XSS에 취약**합니다. 인증 토큰을 localStorage에 넣는 건 탈취 위험이 있어, `HttpOnly` 쿠키가 더 안전하다는 점을 같이 말하면 좋습니다.

**🔥 예상 꼬리질문**
- Q. localStorage에 JWT를 저장해도 되나요? → A. 가능하지만 XSS로 탈취될 수 있어 권장되지 않습니다. `HttpOnly` 쿠키가 더 안전합니다.
- Q. 저장 가능한 자료형은? → A. 문자열만. 객체는 `JSON.stringify`로 직렬화해서 저장합니다.

<details><summary>📝 한 줄 요약</summary>local(영구)·session(탭 한정) 두 종류. 쿠키와 달리 서버 전송 X·용량 큼. JS 접근 가능 → XSS 주의, 토큰은 HttpOnly 쿠키 권장.</details>

## Q10. `<a>` 태그는 어떻게 사용하나요? 🟡

**💬 30초 답변**
> `<a>`(anchor)는 하이퍼링크를 만드는 태그로, `href`에 이동할 URL을 지정합니다. `target="_blank"`로 새 탭을 열 수 있고, 이때는 보안을 위해 `rel="noopener noreferrer"`를 함께 붙입니다.

**📖 핵심 개념**

```html
<a href="https://example.com">외부 링크</a>
<a href="/about">내부 페이지</a>
<a href="#section1">페이지 내 앵커 이동</a>
<a href="mailto:hi@test.com">이메일</a>
<a href="tel:01012345678">전화</a>
<a href="/file.pdf" download>다운로드</a>
<a href="https://x.com" target="_blank" rel="noopener noreferrer">새 탭</a>
```

📌 **주요 속성**
- `href`: 목적지 (URL, 앵커 `#id`, `mailto:`, `tel:`)
- `target="_blank"`: 새 탭에서 열기
- `rel="noopener noreferrer"`: 새 탭 보안 — 열린 페이지가 `window.opener`로 원본을 조작하는 **탭내빙(tabnabbing)** 공격 방지
- `download`: 링크를 다운로드로 처리

> 💡 **`target="_blank"`엔 항상 `rel="noopener"`**: 이게 없으면 새 탭의 페이지가 `window.opener.location`을 바꿔 피싱 사이트로 원본 탭을 리다이렉트할 수 있습니다. (최신 브라우저는 기본 적용하지만 명시가 안전)

**🔥 예상 꼬리질문**
- Q. `href`가 없는 `<a>`는? → A. 링크가 아닌 placeholder가 되고 키보드 포커스도 못 받습니다. 동작 버튼이 필요하면 `<button>`을 쓰세요.
- Q. SPA에서 `<a>` 대신 무엇? → A. React Router의 `<Link>`, Next.js의 `<Link>` — 전체 새로고침 없이 클라이언트 라우팅합니다.

<details><summary>📝 한 줄 요약</summary>href로 링크. 새 탭(<code>target="_blank"</code>)엔 보안 위해 <code>rel="noopener noreferrer"</code>. SPA에선 프레임워크 Link 사용.</details>

## Q11. `<iframe>` 태그의 장점과 단점은 무엇인가요? 🟢

**💬 30초 답변**
> `<iframe>`은 현재 문서 안에 **다른 HTML 문서를 삽입**하는 태그입니다. 유튜브 영상·지도·결제창처럼 외부 콘텐츠를 격리된 환경에서 임베드할 수 있다는 장점이 있지만, 성능 저하·SEO 불리·보안 위험이라는 단점이 있습니다.

**📖 핵심 개념**

```html
<iframe
  src="https://www.youtube.com/embed/xxxx"
  width="560" height="315"
  loading="lazy"
  sandbox="allow-scripts allow-same-origin"
  title="유튜브 영상">
</iframe>
```

✅ **장점**
- 외부 콘텐츠(영상, 지도, 위젯)를 쉽게 임베드
- 메인 문서와 **격리(sandbox)** → 외부 스크립트로부터 분리
- 결제·로그인 등 민감 영역을 별도 출처로 분리 가능

❌ **단점**
- **성능**: 별도 문서를 추가 로드 → 리소스·메모리 부담
- **SEO**: 검색엔진이 iframe 내부 콘텐츠를 본문으로 잘 인식 못 함
- **반응형 어려움**: 크기 제어가 까다로움
- **보안**: 클릭재킹 등에 악용될 수 있음 → `sandbox`, CSP의 `frame-ancestors`로 방어

> 💡 보안 키워드: 내 사이트가 남의 iframe에 끼워지는 **클릭재킹** 방지는 `X-Frame-Options` 또는 CSP `frame-ancestors`로, 내가 삽입하는 iframe 제어는 `sandbox` 속성으로.

**🔥 예상 꼬리질문**
- Q. iframe 성능을 개선하려면? → A. `loading="lazy"`로 지연 로드, 필요한 시점에만 삽입.
- Q. 부모-자식 iframe 간 통신은? → A. `window.postMessage`로 출처를 검증하며 메시지를 주고받습니다.

<details><summary>📝 한 줄 요약</summary>다른 문서를 임베드. 장점=격리·외부 콘텐츠 삽입 / 단점=성능·SEO·보안(클릭재킹). sandbox·lazy·postMessage 기억.</details>

## Q12. 헤딩 태그란 무엇인가요? 🟡

**💬 30초 답변**
> 헤딩 태그(`<h1>`~`<h6>`)는 문서의 **제목 계층**을 나타내는 태그입니다. `h1`이 가장 중요하고 `h6`이 가장 낮으며, 숫자를 건너뛰지 않고 순서대로 사용해 문서의 아웃라인을 만드는 것이 중요합니다.

**📖 핵심 개념**

```
h1  문서의 대주제 (페이지당 1개 권장)
 └ h2  섹션
     └ h3  하위 섹션
         └ h4 ...
```

📌 **규칙**
- **계층을 건너뛰지 않기**: `h1` 다음에 `h3`로 점프 ❌ → 스크린리더 아웃라인이 깨짐
- **크기 때문에 선택하지 않기**: "글자가 커서 h1" ❌ → 크기는 CSS로, 태그는 **의미(중요도)** 로 선택
- **h1은 페이지에 하나** 권장 (SEO·접근성)

```html
<!-- ❌ 크기 목적으로 잘못 사용 -->
<h1>그냥 큰 글씨</h1>
<h4>본문 제목인데 작게</h4>

<!-- ✅ 의미에 맞게 -->
<h1>블로그 글 제목</h1>
<h2>소제목</h2>
<p style="font-size:2rem">큰 글씨는 CSS로</p>
```

**🔥 예상 꼬리질문**
- Q. h1을 여러 개 쓰면 안 되나요? → A. HTML5 섹셔닝상 기술적으로 가능하지만, SEO·접근성 관점에서 페이지당 1개를 권장합니다.
- Q. 왜 순서가 중요한가요? → A. 스크린리더 사용자는 헤딩 목록으로 페이지를 탐색하므로, 계층이 어긋나면 구조 파악이 어렵습니다.

<details><summary>📝 한 줄 요약</summary>h1~h6 제목 계층. 건너뛰지 말고 순서대로, 크기가 아닌 <b>의미(중요도)</b>로 선택. h1은 페이지당 1개.</details>

## Q13. HTML 엔티티란 무엇인가요? 🟢

**💬 30초 답변**
> HTML 엔티티는 `<`, `>`, `&`처럼 **HTML 문법으로 예약된 문자**나 특수문자를 화면에 그대로 표시하기 위한 표기법입니다. `&lt;`, `&gt;`, `&amp;` 같은 코드로 작성합니다.

**📖 핵심 개념**

🎯 **왜 필요한가**: `<`를 그냥 쓰면 브라우저가 "태그 시작"으로 해석합니다. 글자 그대로 보여주려면 엔티티로 이스케이프해야 합니다.

| 문자 | 엔티티 | 이름 |
|------|--------|------|
| `<` | `&lt;` | less than |
| `>` | `&gt;` | greater than |
| `&` | `&amp;` | ampersand |
| `"` | `&quot;` | 큰따옴표 |
| (공백) | `&nbsp;` | 줄바꿈 안 되는 공백 |
| `©` | `&copy;` | 저작권 |

```html
<!-- 코드 예시를 글자로 보여줄 때 -->
<code>&lt;div&gt;&lt;/div&gt;</code>
<!-- 화면 출력: <div></div> -->
```

> ⚠️ **보안 연결**: 사용자 입력을 그대로 HTML에 넣으면 `<script>`가 실행되는 **XSS**가 발생합니다. 이를 막으려고 `<`→`&lt;` 등으로 변환하는 것을 **이스케이프(escaping)** 라 하며, React는 JSX에서 이를 자동 처리합니다.

**🔥 예상 꼬리질문**
- Q. `&nbsp;`는 왜 쓰나요? → A. 연속 공백이 하나로 합쳐지는 걸 막거나, 단어가 줄바꿈으로 끊기지 않게 할 때.
- Q. XSS와의 관계는? → A. 입력값을 엔티티로 이스케이프하면 스크립트가 코드가 아닌 텍스트로 처리되어 실행되지 않습니다.

<details><summary>📝 한 줄 요약</summary>예약 문자(<,>,&)를 글자로 표시하는 표기(<code>&lt; &gt; &amp;</code>). 입력 이스케이프로 XSS 방어와 직결.</details>

## Q14. `<img>` 태그의 srcset 속성은 언제 사용하나요? 🟡

**💬 30초 답변**
> `srcset`은 **여러 해상도의 이미지를 제공**하고 브라우저가 화면 크기·픽셀 밀도에 맞는 최적 이미지를 고르게 하는 속성입니다. 고해상도(레티나) 대응과 반응형 이미지로 불필요한 대용량 다운로드를 막아 성능을 높입니다.

**📖 핵심 개념**

📌 **두 가지 사용 방식**

1) **픽셀 밀도(`x`)** — 레티나 대응
```html
<img src="logo.png"
     srcset="logo.png 1x, logo@2x.png 2x, logo@3x.png 3x"
     alt="로고">
```

2) **뷰포트 너비(`w`) + sizes** — 반응형
```html
<img
  src="small.jpg"
  srcset="small.jpg 480w, medium.jpg 800w, large.jpg 1200w"
  sizes="(max-width: 600px) 480px, 800px"
  alt="배너">
```
- `srcset`: 이미지 후보와 각 **실제 너비(w)**
- `sizes`: 뷰포트 조건별로 이미지가 차지할 **표시 너비** → 브라우저가 이 둘로 최적 후보 선택

🎯 **효과**: 모바일에 1200px 이미지를 내려받는 낭비를 막아 **로딩 성능·데이터 절약**.

> 💡 Next.js의 `<Image>`는 이 srcset/sizes·lazy loading·포맷 변환을 자동으로 처리해줍니다(Q69 연결).

**🔥 예상 꼬리질문**
- Q. `srcset`만 쓰고 `src`는 생략해도 되나요? → A. `src`는 미지원 브라우저 폴백용으로 두는 게 안전합니다.
- Q. `<picture>`와의 차이는? → A. `srcset`은 같은 이미지의 해상도 선택, `<picture>`는 포맷(webp/avif)이나 아트 디렉션(잘라낸 다른 구도)까지 분기할 때 사용.

<details><summary>📝 한 줄 요약</summary>해상도·뷰포트별 최적 이미지를 브라우저가 고르게 하는 속성(<code>1x/2x</code> 또는 <code>w</code>+sizes). 성능·레티나 대응.</details>

## Q15. `<canvas>` 태그란 무엇인가요? 🟢

**💬 30초 답변**
> `<canvas>`는 JavaScript로 **픽셀 단위 그래픽을 그리는 영역**을 만드는 태그입니다. 차트, 게임, 이미지 편집, 시각화처럼 동적이고 복잡한 그래픽에 사용하며, 2D Context나 WebGL로 그립니다.

**📖 핵심 개념**

```html
<canvas id="c" width="300" height="150"></canvas>
<script>
  const ctx = document.getElementById('c').getContext('2d');
  ctx.fillStyle = 'tomato';
  ctx.fillRect(20, 20, 100, 60);   // 사각형
</script>
```

📌 **canvas vs SVG (면접 단골 비교!)**

| 구분 | canvas | SVG |
|------|--------|-----|
| 방식 | **래스터**(픽셀) | **벡터**(도형 + DOM) |
| 확대 | 깨짐 | 무한 선명 |
| 요소 접근 | 그린 후 개별 요소 제어 ❌ | 각 도형이 DOM 요소 ✅ |
| 성능 | 객체 많을 때 유리(게임) | 객체 적고 상호작용 많을 때 유리 |
| 용도 | 게임, 대량 데이터 시각화 | 아이콘, 로고, 인터랙티브 차트 |

🎯 **언제 canvas?**: 초당 수십 프레임을 다시 그리는 게임, 수만 개 점을 찍는 데이터 시각화처럼 **DOM으로는 무거운 경우**.

> ⚠️ canvas는 그린 결과가 픽셀이라 **접근성이 약함** — 대체 텍스트나 인접 설명을 별도로 제공해야 합니다.

**🔥 예상 꼬리질문**
- Q. 차트 라이브러리는 보통 무엇을 쓰나요? → A. Chart.js는 canvas, D3는 주로 SVG 기반(둘 다 가능). 상호작용·접근성 중요하면 SVG, 대량·고성능이면 canvas.

<details><summary>📝 한 줄 요약</summary>JS로 픽셀(래스터) 그래픽을 그리는 영역. 게임·대량 시각화에 강함. 확대 시 깨지고 접근성 약함 → 정밀·인터랙티브는 SVG.</details>

## Q16. HTML 인코딩이란 무엇인가요? 🟢

**💬 30초 답변**
> HTML 인코딩은 크게 두 의미가 있습니다. ① **문자 인코딩**: 텍스트를 바이트로 저장·해석하는 방식으로 `<meta charset="UTF-8">`로 지정해 한글 깨짐을 막습니다. ② **엔티티 인코딩**: `<`,`&` 같은 특수문자를 `&lt;`,`&amp;`로 변환해 안전하게 표시하는 것입니다.

**📖 핵심 개념**

📌 **① 문자 인코딩 (charset)**
- 컴퓨터는 글자를 숫자(바이트)로 저장 → 어떤 규칙으로 변환할지가 인코딩
- **UTF-8**: 전 세계 문자를 표현하는 사실상 표준. 한글·이모지 모두 지원
- 잘못되면: `한글` → `ÇÑ±Û` 같은 깨짐(mojibake)
```html
<meta charset="UTF-8" />  <!-- head 최상단 -->
```

📌 **② 엔티티 인코딩 (escaping)**
- 특수문자를 엔티티로 변환 (`<` → `&lt;`)
- 목적: 의도대로 표시 + **XSS 방어** (Q13 연결)

```
원본 입력:  <script>alert(1)</script>
인코딩 후:  &lt;script&gt;alert(1)&lt;/script&gt;
→ 스크립트로 실행되지 않고 글자로 표시됨
```

🎯 **연관 개념**: URL 인코딩(퍼센트 인코딩, 공백→`%20`), Base64 인코딩(Q82)도 "데이터를 다른 형식으로 변환"이라는 큰 틀에서 함께 묶어 이해하면 좋습니다.

**🔥 예상 꼬리질문**
- Q. charset 선언을 빼면? → A. 브라우저가 인코딩을 추측하다 한글이 깨질 수 있습니다.
- Q. 왜 UTF-8을 쓰나요? → A. 가변 길이로 다국어·이모지를 모두 표현하면서 ASCII와 호환되어 사실상 웹 표준입니다.

<details><summary>📝 한 줄 요약</summary>① 문자 인코딩(UTF-8, 깨짐 방지) ② 엔티티 인코딩(특수문자→엔티티, XSS 방어). meta charset은 head 최상단.</details>

## Q17. `<svg>` 태그는 어떤 용도로 사용하나요? 🟡

**💬 30초 답변**
> SVG(Scalable Vector Graphics)는 **벡터 기반의 그래픽**을 XML로 기술하는 태그입니다. 확대해도 깨지지 않아 아이콘·로고·일러스트에 적합하고, 각 도형이 DOM 요소라서 CSS·JS로 스타일링과 상호작용 제어가 가능합니다.

**📖 핵심 개념**

```html
<svg width="100" height="100" viewBox="0 0 100 100">
  <circle cx="50" cy="50" r="40" fill="tomato" />
  <text x="50" y="55" text-anchor="middle">Hi</text>
</svg>
```

✅ **장점**
- **무한 확대 선명** (벡터) → 레티나·고해상도 완벽 대응
- **CSS/JS 제어 가능** (도형이 DOM 요소 → hover, 애니메이션, 색 변경)
- 작은 파일 크기 (단순 도형의 경우)
- 인라인 삽입 시 추가 HTTP 요청 불필요

❌ **단점**
- 복잡한 사진·그라데이션엔 부적합(노드 폭증 → 무거움)
- 매우 많은 요소를 동시에 다루면 canvas보다 느림

🎯 **언제 SVG?**: 아이콘, 로고, 인터랙티브 차트(hover 툴팁 등). 반대로 게임·대량 픽셀 처리는 canvas(Q15 연결).

> 💡 사용 방법 3가지: ① 인라인 `<svg>`(CSS/JS 제어 best) ② `<img src="icon.svg">`(간단, 제어 X) ③ CSS `background-image`. 색을 동적으로 바꾸려면 인라인이 유리합니다.

**🔥 예상 꼬리질문**
- Q. SVG vs PNG 아이콘? → A. SVG는 확대해도 선명하고 색 변경이 쉬워 아이콘에 우수. PNG는 복잡한 사진에 적합.
- Q. `viewBox`는 무엇? → A. SVG 내부 좌표계와 보이는 영역을 정의해 반응형 스케일링의 기준이 됩니다.

<details><summary>📝 한 줄 요약</summary>벡터 그래픽(XML). 확대해도 선명·CSS/JS 제어 가능 → 아이콘·로고·인터랙티브 차트. 사진·대량 요소엔 부적합(→canvas).</details>
