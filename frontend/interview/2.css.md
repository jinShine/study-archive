## Q18. CSS란 무엇인가요? 🟡

**💬 30초 답변**
> CSS(Cascading Style Sheets)는 HTML로 만든 구조에 **색·레이아웃·폰트 등 시각적 표현을 입히는 스타일 언어**입니다. 'Cascading(폭포처럼 흘러내리는)'은 여러 스타일 규칙이 우선순위에 따라 적용되는 계단식 적용 방식을 뜻합니다.

**📖 핵심 개념**

🎯 **비유**: HTML이 집의 골조라면 CSS는 **인테리어**입니다. 같은 골조라도 인테리어에 따라 전혀 다른 집이 됩니다.

📌 **Cascading(계단식)의 의미**: 한 요소에 여러 규칙이 겹칠 때, ① **명시도(specificity)** ② **소스 순서** ③ **중요도(`!important`)** 에 따라 최종 스타일이 결정됩니다.

📌 **적용 방법 3가지**
```html
<!-- ① 인라인 (명시도 가장 높음, 비권장) -->
<p style="color:red">텍스트</p>

<!-- ② 내부 스타일 -->
<style> p { color: red; } </style>

<!-- ③ 외부 스타일 (권장: 관심사 분리) -->
<link rel="stylesheet" href="style.css">
```

**🔥 예상 꼬리질문**
- Q. Cascading이 무슨 뜻인가요? → A. 여러 스타일 규칙이 우선순위(명시도·순서·중요도)에 따라 폭포처럼 흘러 적용되는 방식.
- Q. 관심사 분리가 왜 중요? → A. 구조(HTML)·표현(CSS)·동작(JS)을 분리하면 유지보수와 재사용이 쉬워집니다.

<details><summary>📝 한 줄 요약</summary>HTML 구조에 시각적 표현을 입히는 스타일 언어. Cascading = 명시도·순서·중요도로 규칙이 계단식 적용.</details>

## Q19. CSS 선택자와 선택자 우선순위를 설명할 수 있나요? 🔴

**💬 30초 답변**
> 선택자는 스타일을 적용할 대상을 고르는 패턴이고, 여러 규칙이 충돌할 때는 **명시도(specificity)** 로 우선순위를 정합니다. 명시도는 `인라인 > id > class·속성·가상클래스 > 태그` 순이며, 같으면 **나중에 선언된 규칙**이 이깁니다.

**📖 핵심 개념**

📌 **명시도 점수 (a, b, c)**

| 구분 | 가중치 | 예 |
|------|:---:|----|
| 인라인 스타일 | 1,0,0,0 | `style="..."` |
| id | 0,1,0,0 | `#header` |
| class · 속성 · 가상클래스 | 0,0,1,0 | `.btn`, `[type]`, `:hover` |
| 태그 · 가상요소 | 0,0,0,1 | `div`, `::before` |
| 전체 선택자 `*` | 0,0,0,0 | 가중치 없음 |

```
#nav .item a    → 0,1,1,1
.item .link     → 0,0,2,0
→ 첫 번째가 id를 포함해 우선
```

📌 **우선순위 결정 순서**
1. `!important` (최강 — 남용 금지)
2. 명시도 점수
3. **소스 순서** (같은 명시도면 나중 선언 승리)

```css
/* ❌ !important 남발 → 유지보수 지옥 */
.btn { color: red !important; }

/* ✅ 명시도를 낮게 유지하고 순서로 관리 */
.btn { color: red; }
.btn.btn--primary { color: blue; }
```

> 💡 명시도를 낮고 평평하게 유지하는 게 핵심 — `:where()`(Q34)는 명시도 0이라 덮어쓰기 쉬운 기본 스타일에 유용합니다.

**🔥 예상 꼬리질문**
- Q. `!important`보다 강한 건? → A. 다른 규칙의 `!important`거나, 인라인 스타일의 `!important`. 그래서 가급적 안 쓰는 게 정답.
- Q. 명시도가 같으면? → A. CSS 파일에서 더 아래(나중)에 선언된 규칙이 적용됩니다.

<details><summary>📝 한 줄 요약</summary>대상을 고르는 패턴. 우선순위 = !important > 명시도(인라인>id>class>태그) > 소스 순서. !important 남용 금지.</details>

## Q20. 가상 클래스와 가상 요소의 차이점은 무엇인가요? 🟡

**💬 30초 답변**
> **가상 클래스**(`:`)는 요소의 **특정 상태**를 선택하고(`:hover`, `:focus`, `:nth-child`), **가상 요소**(`::`)는 실제로 없는 **가상의 부분을 만들어** 스타일링합니다(`::before`, `::after`). 콜론 개수(`:` vs `::`)로 구분합니다.

**📖 핵심 개념**

📌 **가상 클래스 (pseudo-class, `:`)** — "어떤 상태일 때"
```css
a:hover { color: red; }          /* 마우스 올렸을 때 */
input:focus { border: blue; }    /* 포커스 받을 때 */
li:first-child { font-weight: bold; }
li:nth-child(2n) { background: #eee; }  /* 짝수 */
button:disabled { opacity: .5; }
```

📌 **가상 요소 (pseudo-element, `::`)** — "없는 부분을 생성/선택"
```css
.tooltip::before { content: "💡"; }   /* 가상 요소 생성, content 필수 */
p::first-line { font-weight: bold; }   /* 첫 줄만 */
::selection { background: yellow; }    /* 드래그 선택 영역 */
```

```
:hover     → 이미 있는 요소의 '상태'를 선택
::before   → 없던 콘텐츠를 '새로 생성'
```

> 💡 `::before`/`::after`는 반드시 **`content` 속성**이 있어야 렌더링됩니다(`content: ""`라도). CSS3에서 가상 요소는 `::`로 구분하지만 `:before`도 하위 호환으로 동작합니다.

**🔥 예상 꼬리질문**
- Q. 콜론 한 개와 두 개의 차이는? → A. `:`는 가상 클래스(상태), `::`는 가상 요소(생성). CSS3에서 시각적으로 구분하려 도입.
- Q. `::before`의 활용 예? → A. 아이콘 삽입, 말풍선 꼬리, 장식선, clearfix 등.

<details><summary>📝 한 줄 요약</summary>가상 클래스(:)=요소의 상태 선택(:hover) / 가상 요소(::)=없는 부분 생성(::before, content 필수).</details>

## Q21. `<img>` 태그와 CSS background-image 속성은 각각 언제 사용해야 하나요? 🟡

**💬 30초 답변**
> 이미지가 **콘텐츠로서 의미**를 가지면(로고, 상품 사진, 본문 그림) `<img>`를, 순수 **장식**이면(배경 패턴, 그라데이션) `background-image`를 씁니다. 핵심 기준은 "이 이미지가 사라지면 정보가 손실되는가"입니다.

**📖 핵심 개념**

📌 **비교**

| 구분 | `<img>` | `background-image` |
|------|---------|--------------------|
| 의미 | 콘텐츠 (의미 있음) | 장식 (의미 없음) |
| 접근성 | `alt`로 대체텍스트 ✅ | 스크린리더가 안 읽음 |
| SEO | 검색 인식 ✅ | 인식 ❌ |
| 제어 | `srcset` 반응형, lazy | `background-size/position`로 유연 배치 |
| 우클릭 저장 | 가능 | 어려움 |

```html
<!-- ✅ 콘텐츠: 의미 있는 이미지 -->
<img src="product.jpg" alt="빨간 운동화">
```
```css
/* ✅ 장식: 배경 패턴/그라데이션 */
.hero { background-image: url("pattern.png"); background-size: cover; }
```

🎯 **판단 기준**: 이미지가 없을 때 **정보가 빠지면 `<img>`+alt**, 그냥 밋밋해질 뿐이면 **background-image**.

**🔥 예상 꼬리질문**
- Q. 히어로 배너 큰 이미지는? → A. 의미 있는 콘텐츠면 `<img>`(+lazy/srcset), 단순 배경 분위기면 background. SEO·LCP 고려 시 `<img>`가 유리한 경우가 많음.
- Q. 아이콘은? → A. 의미 있으면 `<img alt>` 또는 인라인 SVG, 순수 장식이면 background나 `::before`.

<details><summary>📝 한 줄 요약</summary>의미 있는 콘텐츠 이미지=<code>&lt;img&gt;</code>+alt(접근성·SEO) / 순수 장식=<code>background-image</code>(유연 배치).</details>

## Q22. 박스 모델이란 무엇인가요? 🔴

**💬 30초 답변**
> 모든 HTML 요소는 **content → padding → border → margin** 네 겹의 사각형 박스로 구성되며, 이를 박스 모델이라 합니다. `box-sizing` 값에 따라 width 계산에 padding·border가 포함되는지(`border-box`)가 달라집니다.

**📖 핵심 개념**

```
┌─────────── margin (요소 바깥 여백) ───────────┐
│  ┌──────── border (테두리) ──────────┐        │
│  │  ┌───── padding (안쪽 여백) ────┐  │        │
│  │  │      content (내용)         │  │        │
│  │  └──────────────────────────────┘  │        │
│  └────────────────────────────────────┘        │
└──────────────────────────────────────────────┘
```

📌 **`box-sizing` (면접 핵심!)**

| 값 | width 계산 | 비고 |
|----|-----------|------|
| `content-box` (기본) | width = **content만** | padding/border가 더해져 실제 박스가 커짐 |
| `border-box` | width = **content+padding+border** | 지정한 width가 곧 박스 크기 → 직관적 |

```css
/* ❌ content-box: width 200 + padding 40 + border 4 = 실제 244px */
.box { width: 200px; padding: 20px; border: 2px solid; }

/* ✅ 실무 표준: 전체 border-box로 통일 */
*, *::before, *::after { box-sizing: border-box; }
/* → width 200px가 곧 실제 너비 (계산 편함) */
```

> 💡 거의 모든 프로젝트가 reset에서 `box-sizing: border-box`를 전역 적용합니다. "왜?"는 width 계산이 직관적이기 때문.

**🔥 예상 꼬리질문**
- Q. margin 상쇄(collapse)란? → A. 인접한 블록 요소의 상하 margin이 합쳐지지 않고 더 큰 값 하나로 합쳐지는 현상.
- Q. border-box를 쓰는 이유? → A. padding을 늘려도 전체 width가 변하지 않아 레이아웃 계산이 예측 가능.

<details><summary>📝 한 줄 요약</summary>content+padding+border+margin 4겹 박스. box-sizing: border-box면 width에 padding·border 포함 → 실무 표준.</details>

## Q23. 전처리기란 무엇인가요? 🟢

**💬 30초 답변**
> CSS 전처리기(preprocessor)는 변수·중첩·믹스인·함수 같은 프로그래밍 기능을 더해 CSS를 더 효율적으로 작성하게 해주는 도구입니다. Sass/SCSS, Less가 대표적이며, 작성한 코드는 빌드 시 **순수 CSS로 컴파일**됩니다.

**📖 핵심 개념**

📌 **전처리기가 주는 것**: 변수, 중첩(nesting), 믹스인(mixin), 함수, 모듈 분리(`@import`/`@use`)

```scss
// SCSS 예시
$primary: #3498db;          // 변수

.card {
  color: $primary;
  &:hover { color: darken($primary, 10%); }  // 중첩 + 함수
  .title { font-weight: bold; }               // 중첩
}

@mixin flex-center {         // 믹스인 (재사용 블록)
  display: flex; align-items: center; justify-content: center;
}
.box { @include flex-center; }
```

🎯 **컴파일 흐름**: `style.scss` → (Sass 컴파일러) → `style.css` → 브라우저는 순수 CSS만 읽음.

> 💡 **요즘 흐름**: 네이티브 CSS가 변수(`--var`), 중첩을 지원하면서 전처리기 의존이 줄고, **PostCSS**(후처리기)나 **CSS-in-JS**, **Tailwind** 등으로 다양화됨. "전처리기 vs 네이티브 CSS 변수" 차이를 알면 좋음.

**🔥 예상 꼬리질문**
- Q. CSS 변수(`--var`)와 Sass 변수의 차이? → A. CSS 변수는 런타임에 동적 변경·미디어쿼리 반응 가능, Sass 변수는 컴파일 시점에 고정.
- Q. 전처리기 vs 후처리기(PostCSS)? → A. 전처리기는 컴파일 전 확장 문법, PostCSS는 작성된 CSS를 변환(autoprefixer 등).

<details><summary>📝 한 줄 요약</summary>변수·중첩·믹스인으로 CSS를 확장(Sass/Less). 빌드 시 순수 CSS로 컴파일. 요즘은 네이티브 변수·PostCSS·CSS-in-JS와 공존.</details>

## Q24. display: none, visibility: hidden, opacity: 0의 차이점은 무엇인가요? 🔴

**💬 30초 답변**
> 셋 다 요소를 안 보이게 하지만, **공간 차지**와 **이벤트 반응**이 다릅니다. `display:none`은 공간도 없고 이벤트도 없음(DOM엔 존재), `visibility:hidden`은 공간은 차지하되 안 보이고 이벤트 없음, `opacity:0`은 공간도 차지하고 **클릭 등 이벤트도 그대로 반응**합니다.

**📖 핵심 개념**

📌 **비교표 (면접 단골!)**

| 속성 | 화면 표시 | 공간 차지 | 이벤트(클릭) | 트랜지션 | 접근성(스크린리더) |
|------|:---:|:---:|:---:|:---:|:---:|
| `display: none` | ❌ | ❌ | ❌ | 불가 | 읽지 않음 |
| `visibility: hidden` | ❌ | ✅ | ❌ | 가능 | 읽지 않음 |
| `opacity: 0` | ❌ | ✅ | ✅ | **가능(부드러움)** | **읽음** |

```
display:none      → 레이아웃에서 완전히 빠짐 (reflow 발생)
visibility:hidden → 자리는 그대로, 투명 인간처럼 안 보임
opacity:0         → 자리 그대로 + 클릭됨 → 안 보이는 버튼 클릭 버그 주의!
```

🎯 **언제 무엇을?**
- 완전히 제거(공간도): `display:none`
- 자리 유지하며 숨김: `visibility:hidden`
- **페이드 인/아웃 애니메이션**: `opacity` (transition 가능). 단 숨길 땐 `pointer-events:none`이나 `visibility`를 함께 줘야 클릭 버그 방지.

```css
/* ✅ 부드러운 페이드 + 클릭 차단 */
.modal { opacity: 0; visibility: hidden; transition: opacity .3s; }
.modal.open { opacity: 1; visibility: visible; }
```

**🔥 예상 꼬리질문**
- Q. 애니메이션에 display:none이 안 되는 이유? → A. `display`는 트랜지션 대상이 아니라 즉시 사라져 부드러운 효과가 안 납니다. (`@starting-style`로 일부 해결 가능)
- Q. opacity:0의 함정은? → A. 안 보여도 클릭 영역이 살아있어 뒤 요소 클릭을 가로챕니다 → `pointer-events:none` 필요.

<details><summary>📝 한 줄 요약</summary>none=공간X·이벤트X·DOM유지 / hidden=공간O·이벤트X / opacity:0=공간O·<b>이벤트O</b>·애니메이션 가능(클릭 버그 주의).</details>

## Q25. z-index가 의도대로 동작하지 않는 경우 어떤 것을 확인해야 할까요? 🔴

**💬 30초 답변**
> 가장 먼저 **`position`이 static이 아닌지**(relative/absolute/fixed/sticky), 그리고 **쌓임 맥락(stacking context)** 을 확인합니다. 부모가 별도의 stacking context를 만들면 자식의 z-index가 아무리 커도 그 맥락 밖 요소를 넘지 못합니다.

**📖 핵심 개념**

📌 **체크리스트**
1. **position이 있는가?** — `z-index`는 `position: static`(기본)엔 적용 안 됨 (flex/grid 아이템은 예외적으로 적용)
2. **stacking context에 갇혔는가?** — 부모가 새 쌓임 맥락을 만들면 자식 z-index는 그 안에서만 비교됨
3. **부모의 z-index가 더 낮은가?** — 형제 비교는 부모 맥락 기준

📌 **stacking context를 만드는 주요 조건**
- `position` + `z-index`(auto 아님)
- `opacity` < 1
- `transform`, `filter`, `will-change`, `perspective`
- `isolation: isolate`

```
부모A (z-index:1, stacking context 생성)
 └ 자식 (z-index:9999)   ← 9999여도 A의 맥락 안!
부모B (z-index:2)
 └ 자식 (z-index:1)      ← 이 자식이 위에 옴 (B>A 이므로)
```

```css
/* ❌ 자식 z-index를 키워도 안 먹음 */
.parent { opacity: 0.9; }            /* ← 여기서 맥락 생성됨 */
.child  { z-index: 99999; }

/* ✅ 부모의 맥락/순서를 조정하거나 isolation 활용 */
```

> 💡 가장 흔한 실수: **`transform`이나 `opacity`를 준 부모** 때문에 모달·드롭다운이 의도대로 안 올라옴. "z-index 안 먹어요" 디버깅의 80%는 이것.

**🔥 예상 꼬리질문**
- Q. position 없이 z-index 적용되는 경우? → A. flex/grid 컨테이너의 아이템은 position 없이도 z-index가 동작합니다.
- Q. isolation:isolate는 왜 쓰나? → A. position/z-index 없이도 새 쌓임 맥락을 만들어 자식의 z-index를 외부와 격리할 때.

<details><summary>📝 한 줄 요약</summary>① position 있는지 ② stacking context에 갇혔는지(부모의 transform/opacity/filter가 주범) ③ 부모 z-index 비교. flex/grid는 position 없이도 적용.</details>

## Q26. 인라인 스타일 요소와 블록 스타일 요소를 가운데 정렬하는 방법은 무엇인가요? 🟡

**💬 30초 답변**
> **인라인/인라인블록 요소**는 부모에 `text-align: center`로 수평 중앙 정렬하고, **블록 요소**는 너비를 정한 뒤 `margin: 0 auto`로 가운데 정렬합니다. 요즘은 둘 다 부모에 flexbox(`justify-content: center`)를 쓰는 게 가장 간단합니다.

**📖 핵심 개념**

📌 **요소 타입별 수평 중앙 정렬**

```css
/* ① 인라인/인라인블록 요소 (텍스트, span, img) → 부모에 */
.parent { text-align: center; }

/* ② 블록 요소 → 너비 + 좌우 auto margin */
.block { width: 300px; margin: 0 auto; }

/* ③ 만능: flexbox (요즘 표준) */
.parent { display: flex; justify-content: center; }
```

```
text-align:center → 인라인 콘텐츠를 부모 안에서 중앙
margin:0 auto     → 블록 요소 자신을 부모 안에서 중앙 (width 필수!)
```

> 💡 `margin: 0 auto`가 안 먹는 가장 흔한 이유: **width가 없어서**(블록은 기본 width 100%라 가운데 갈 여백이 없음). width를 지정해야 좌우 auto가 남는 공간을 균등 분배합니다.

**🔥 예상 꼬리질문**
- Q. `margin: auto`로 수직 중앙도 되나요? → A. 일반 블록 흐름에선 안 됩니다. 단 **flex/grid 아이템에선 `margin: auto`로 수직 중앙도 가능**합니다.
- Q. 인라인 요소에 `margin:0 auto`가 안 되는 이유? → A. 인라인 요소는 width가 적용 안 되고 좌우 margin 자동 계산이 안 되기 때문.

<details><summary>📝 한 줄 요약</summary>인라인=부모에 <code>text-align:center</code> / 블록=<code>width</code>+<code>margin:0 auto</code> / 만능=부모 flex <code>justify-content:center</code>.</details>

## Q27. vertical-align은 왜 수직 정렬이 잘 안 될까요? 🟡

**💬 30초 답변**
> `vertical-align`은 **인라인·인라인블록·테이블셀 요소에만** 적용되고, 블록 요소에는 아무 효과가 없기 때문입니다. 또한 "요소를 부모 중앙에"가 아니라 "같은 줄의 다른 인라인 요소들과의 기준선(baseline)을 맞추는" 속성이라 오해가 많습니다.

**📖 핵심 개념**

❌ **흔한 오해**: "vertical-align: middle 하면 부모 안에서 수직 중앙 가겠지" → 블록 요소엔 무시됨

📌 **실제 동작**: `vertical-align`은 **인라인 레벨 박스끼리** 또는 **테이블 셀 안에서**만 작동
```css
/* ✅ 인라인 요소들의 baseline 정렬 */
.icon { vertical-align: middle; }   /* 텍스트 옆 아이콘 정렬에 유효 */

/* ✅ 테이블 셀 */
td { vertical-align: middle; }
```

✅ **블록 요소 수직 중앙 정렬 — 요즘 방법**
```css
/* flexbox */
.parent { display: flex; align-items: center; }

/* grid */
.parent { display: grid; place-items: center; }
```

```
vertical-align: middle
 → "줄(line box) 안에서 인라인 요소의 세로 정렬"
 → 부모 박스 중앙 정렬과 무관!
```

**🔥 예상 꼬리질문**
- Q. 그럼 수직 중앙은 뭘로? → A. flexbox `align-items: center` 또는 grid `place-items: center`가 표준.
- Q. vertical-align이 유효한 대표 케이스? → A. 텍스트 옆 아이콘·이미지 정렬, 테이블 셀 내 콘텐츠 정렬.

<details><summary>📝 한 줄 요약</summary>인라인·인라인블록·테이블셀에만 적용. 블록엔 무효. baseline 정렬용이라 부모 중앙 정렬과 무관 → 수직 중앙은 flex/grid로.</details>

## Q28. 요소를 중앙 정렬하는 대표적인 방법은 무엇인가요? 🔴

**💬 30초 답변**
> 가장 권장되는 건 **flexbox**(`display:flex; justify-content:center; align-items:center;`)와 **grid**(`display:grid; place-items:center;`)입니다. 한 줄로 수평·수직을 동시에 처리할 수 있어 가장 깔끔합니다.

**📖 핵심 개념**

📌 **대표 4가지 방법**

```css
/* ① flexbox (가장 많이 씀) */
.parent { display: flex; justify-content: center; align-items: center; }

/* ② grid (가장 짧음) */
.parent { display: grid; place-items: center; }

/* ③ absolute + transform (부모 크기 몰라도 됨) */
.parent { position: relative; }
.child  { position: absolute; top: 50%; left: 50%;
          transform: translate(-50%, -50%); }

/* ④ absolute + margin auto */
.child { position: absolute; inset: 0; margin: auto;
         width: 100px; height: 100px; }
```

📌 **선택 가이드**

| 상황 | 추천 |
|------|------|
| 일반적 중앙 정렬 | flex / grid |
| 가장 짧게 | grid `place-items:center` |
| 부모 기준 떠 있는 요소(모달) | absolute + transform |
| 크기 아는 요소 | absolute + margin auto |

> 💡 `transform: translate(-50%,-50%)`는 요소 **자기 크기의 절반만큼** 되돌려, 크기를 몰라도 정확히 중앙에 놓는 고전 테크닉.

**🔥 예상 꼬리질문**
- Q. transform 방식의 장점은? → A. 자식 크기를 몰라도 되고, 부모 레이아웃에 영향(reflow)을 안 줘 모달 등에 적합.
- Q. flex와 grid 중 중앙 정렬은? → A. 둘 다 가능. 한 요소만 중앙이면 grid `place-items`가 가장 짧고, 다른 정렬과 섞이면 flex가 유연.

<details><summary>📝 한 줄 요약</summary>flex(<code>justify+align center</code>) / grid(<code>place-items:center</code>) / absolute+<code>transform:translate(-50%,-50%)</code>. 모달은 transform 방식.</details>

## Q29. 미디어 쿼리는 언제 사용하나요? 🟡

**💬 30초 답변**
> 미디어 쿼리는 화면 너비·기기 특성·사용자 설정에 따라 **다른 CSS를 적용**하는 반응형의 핵심 도구입니다. 주로 모바일/태블릿/데스크톱별 레이아웃 분기에 쓰고, 다크모드·인쇄·모션 축소 같은 환경 대응에도 사용합니다.

**📖 핵심 개념**

```css
/* 모바일 퍼스트: 기본은 모바일, 커지면 덮어쓰기 */
.container { display: block; }

@media (min-width: 768px) {       /* 태블릿 이상 */
  .container { display: flex; }
}
@media (min-width: 1024px) {      /* 데스크톱 */
  .container { gap: 2rem; }
}
```

📌 **레이아웃 외 활용**
```css
@media (prefers-color-scheme: dark) { body { background:#111; } }   /* 다크모드 */
@media (prefers-reduced-motion: reduce) { * { animation:none; } }   /* 모션 최소화(접근성) */
@media print { .no-print { display:none; } }                        /* 인쇄 */
```

🎯 **모바일 퍼스트 vs 데스크톱 퍼스트**
- **모바일 퍼스트**(`min-width`): 작은 화면 기본 → 점점 확장. 성능·권장
- 데스크톱 퍼스트(`max-width`): 큰 화면 기본 → 줄여나감

> 💡 미디어 쿼리가 동작하려면 `<meta name="viewport" content="width=device-width, initial-scale=1">`가 필수(Q3 연결). 없으면 모바일이 데스크톱 너비로 렌더링됨.

**🔥 예상 꼬리질문**
- Q. 모바일 퍼스트를 권장하는 이유? → A. 모바일에 불필요한 데스크톱 스타일을 안 깔아 성능·유지보수에 유리.
- Q. 컨테이너 쿼리(`@container`)는? → A. 뷰포트가 아닌 **부모 컨테이너 크기** 기준 반응형 — 컴포넌트 단위 반응형에 적합한 최신 기능.

<details><summary>📝 한 줄 요약</summary>화면 너비·환경별로 다른 CSS 적용(반응형). min-width 모바일 퍼스트 권장. 다크모드·모션축소·인쇄에도 사용. viewport 메타 필수.</details>

## Q30. animation, transition, transform 속성이란 무엇인가요? 🟡

**💬 30초 답변**
> **transform**은 요소를 이동·회전·확대(시각적 변형)하고, **transition**은 한 상태에서 다른 상태로의 변화를 부드럽게 보간하며, **animation**은 keyframes로 여러 단계의 복잡한 움직임을 자동·반복 재생합니다.

**📖 핵심 개념**

📌 **transform** — 변형 (레이아웃에 영향 X)
```css
.box { transform: translate(10px, 20px) rotate(45deg) scale(1.2); }
```

📌 **transition** — 상태 변화 보간 (트리거 필요: hover 등)
```css
.btn { background: blue; transition: background .3s ease; }
.btn:hover { background: red; }   /* 0.3초에 걸쳐 부드럽게 */
```

📌 **animation** — keyframes 기반 자동 재생
```css
@keyframes spin { from { transform: rotate(0); } to { transform: rotate(360deg); } }
.loader { animation: spin 1s linear infinite; }
```

📌 **비교**

| 속성 | 트리거 | 단계 | 반복 |
|------|--------|------|------|
| transition | 상태 변화 필요(hover 등) | 시작→끝 2단계 | ❌ |
| animation | 자동 (트리거 불필요) | keyframes 다단계 | ✅ infinite |
| transform | (속성, 값 자체) | — | — |

> 💡 **성능 핵심**: 애니메이션은 `transform`과 `opacity`만 쓰면 GPU 가속(합성 단계)으로 60fps가 나옵니다. 반면 `width`/`top`/`left`/`margin` 애니메이션은 **reflow/repaint**를 유발해 끊깁니다(Q93 렌더링 연결).

**🔥 예상 꼬리질문**
- Q. transition과 animation 차이? → A. transition은 상태 변화(2단계)에 트리거 필요, animation은 keyframes로 자동·반복 가능.
- Q. 부드러운 애니메이션의 비결? → A. `transform`/`opacity`만 변경해 GPU 합성을 활용, layout을 건드리지 않기.

<details><summary>📝 한 줄 요약</summary>transform=변형(이동/회전/확대) / transition=상태 변화 보간(트리거 필요) / animation=keyframes 자동·반복. transform·opacity만 써야 60fps.</details>

## Q31. 플렉스박스와 그리드의 차이점은 무엇이며, 각각 어떤 상황에 사용하는 것이 더 적합한가요? 🔴

**💬 30초 답변**
> Flexbox는 **1차원**(가로 또는 세로 한 방향) 배치에, Grid는 **2차원**(행과 열을 동시에) 배치에 적합합니다. 내비게이션·버튼 그룹처럼 한 줄 배치는 Flex, 전체 페이지 레이아웃·카드 갤러리처럼 행열 격자는 Grid가 적합합니다.

**📖 핵심 개념**

```
Flexbox (1차원)            Grid (2차원)
→ [A][B][C]               ┌──┬──┬──┐
  한 축(주축) 기준          │A │B │C │
                          ├──┼──┼──┤
                          │D │E │F │
                          └──┴──┴──┘
                          행+열 동시 제어
```

📌 **비교**

| 구분 | Flexbox | Grid |
|------|---------|------|
| 차원 | 1차원 (행 or 열) | 2차원 (행 + 열) |
| 접근 | 콘텐츠 기반(내용 크기로) | 레이아웃 기반(틀 먼저 정의) |
| 적합 | 내비, 버튼 그룹, 정렬, 한 줄 | 페이지 레이아웃, 카드 그리드, 대시보드 |
| 정렬 | `justify-content`/`align-items` | + `grid-template`, `gap`, 영역 배치 |

```css
/* Flex: 한 줄 메뉴 */
.nav { display: flex; gap: 1rem; justify-content: space-between; }

/* Grid: 반응형 카드 갤러리 */
.gallery { display: grid; grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)); gap: 1rem; }
```

🎯 **함께 쓴다**: 페이지 전체 골격은 Grid, 그 안 각 컴포넌트 내부 정렬은 Flex — 실무에선 둘을 조합합니다. "둘 중 뭐가 더 좋냐"가 아니라 **차원에 맞게 선택**.

**🔥 예상 꼬리질문**
- Q. Grid로 1차원도 되는데 왜 Flex? → A. 콘텐츠 크기 기반 정렬·줄바꿈(`flex-wrap`)·공간 분배(`flex-grow`)가 직관적이라 한 방향 배치엔 Flex가 간결.
- Q. `auto-fill`과 `auto-fit` 차이? → A. auto-fill은 빈 트랙을 유지, auto-fit은 빈 트랙을 접어 아이템이 늘어남.

<details><summary>📝 한 줄 요약</summary>Flex=1차원(한 줄 메뉴·정렬), Grid=2차원(페이지 레이아웃·카드 격자). 실무는 골격 Grid + 내부 Flex 조합.</details>

## Q32. BEM은 무엇이며, 사용하는 이유를 설명할 수 있나요? 🟡

**💬 30초 답변**
> BEM은 **Block, Element, Modifier**의 약자로, CSS 클래스 이름을 `block__element--modifier` 규칙으로 짓는 네이밍 방법론입니다. 클래스명만 봐도 구조와 역할이 보이고, 명시도를 평평하게 유지해 스타일 충돌을 줄입니다.

**📖 핵심 개념**

📌 **구성**
- **Block**: 독립적 컴포넌트 (`card`, `menu`)
- **Element**: 블록의 구성 요소, `__`로 연결 (`card__title`)
- **Modifier**: 상태·변형, `--`로 연결 (`card--featured`, `button--disabled`)

```html
<div class="card card--featured">
  <h2 class="card__title">제목</h2>
  <button class="card__button card__button--primary">확인</button>
</div>
```
```css
.card { }
.card--featured { }       /* 변형 */
.card__title { }          /* 요소 */
.card__button--primary { }/* 요소의 변형 */
```

✅ **사용 이유**
- **명시도 평평**: 전부 단일 class(0,0,1,0)라 우선순위 충돌·`!important` 남발 방지(Q19 연결)
- **가독성**: 클래스명만으로 구조·관계 파악
- **재사용·격리**: 다른 블록과 이름이 안 겹쳐 안전

> 💡 요즘은 CSS Modules, Tailwind, CSS-in-JS가 스코프 격리를 자동으로 해줘서 BEM 필요성이 줄었지만, 순수 CSS 협업에선 여전히 강력한 컨벤션.

**🔥 예상 꼬리질문**
- Q. BEM의 단점은? → A. 클래스명이 길고 장황해짐. 깊은 중첩 표현이 어색.
- Q. 대안은? → A. CSS Modules(자동 해시 스코프), Tailwind(유틸리티), styled-components(컴포넌트 스코프).

<details><summary>📝 한 줄 요약</summary>Block__Element--Modifier 네이밍 규칙. 명시도 평평·가독성·격리가 목적. 요즘은 CSS Modules/Tailwind가 대체.</details>

## Q33. @supports 규칙은 언제 사용하나요? 🟢

**💬 30초 답변**
> `@supports`는 브라우저가 특정 CSS 속성을 **지원하는지 검사**해서 조건부로 스타일을 적용하는 기능 쿼리(feature query)입니다. 최신 CSS를 쓰되, 미지원 브라우저에는 대체 스타일(fallback)을 제공하는 점진적 향상에 사용합니다.

**📖 핵심 개념**

```css
/* 기본(폴백): 미지원 브라우저용 */
.layout { display: flex; }

/* grid를 지원하면 grid로 업그레이드 */
@supports (display: grid) {
  .layout { display: grid; grid-template-columns: 1fr 1fr; }
}

/* 미지원 시 적용 (not) */
@supports not (backdrop-filter: blur(10px)) {
  .modal { background: rgba(0,0,0,.8); }  /* blur 대신 진한 배경 */
}
```

🎯 **언제 쓰나**: `backdrop-filter`, `aspect-ratio`, `:has()`, subgrid처럼 **지원이 갈리는 최신 속성**을 안전하게 도입할 때.

```css
/* and / or 조합도 가능 */
@supports (gap: 1rem) and (display: flex) { .row { gap: 1rem; } }
```

> 💡 미디어 쿼리(`@media`)는 "화면 크기/환경" 조건, `@supports`는 "기능 지원 여부" 조건 — 목적이 다름.

**🔥 예상 꼬리질문**
- Q. JS 없이 호환성을 다루는 방법? → A. `@supports` 기능 쿼리, autoprefixer로 벤더 프리픽스 자동 추가.
- Q. 점진적 향상(progressive enhancement)이란? → A. 기본 기능을 모두에게 보장하고, 지원 브라우저엔 향상된 경험을 추가하는 전략.

<details><summary>📝 한 줄 요약</summary>CSS 기능 지원 여부를 검사해 조건부 스타일 적용(feature query). 최신 속성 도입 + 폴백 제공(점진적 향상)에 사용.</details>

## Q34. :is()와 :where() 가상 클래스 선택자의 차이점은 무엇인가요? 🟢

**💬 30초 답변**
> 둘 다 여러 선택자를 묶어 코드를 간결하게 해주지만, **명시도(specificity)** 가 다릅니다. `:is()`는 **인자 중 가장 높은 명시도**를 그대로 가져가고, `:where()`는 **항상 명시도가 0**입니다. 덮어쓰기 쉬운 기본 스타일엔 `:where()`가 유리합니다.

**📖 핵심 개념**

```css
/* 반복 줄이기 — 둘 다 아래와 동치 */
:is(h1, h2, h3) a { color: blue; }
/* = h1 a, h2 a, h3 a { color: blue; } */
```

📌 **핵심 차이: 명시도**
```css
/* :is() → 인자 중 최고 명시도(#id=0,1,0,0)를 가짐 */
:is(#main, .box) p { color: red; }   /* 명시도 = id 수준 (높음) */

/* :where() → 항상 0,0,0,0 */
:where(#main, .box) p { color: red; } /* 명시도 0 → 뒤 규칙이 쉽게 덮음 */
```

```
:is(...)    → 묶되 명시도 유지 (가장 강한 인자 기준)
:where(...) → 묶되 명시도 0 (덮어쓰기 매우 쉬움)
```

🎯 **언제 무엇을?**
- **`:where()`**: 라이브러리·리셋·기본 스타일 — 사용자가 쉽게 덮어쓰게 명시도 0으로
- **`:is()`**: 명시도를 유지한 채 선택자를 그룹화하고 싶을 때

> 💡 둘 다 **forgiving(관용적)** — 인자 목록에 무효한 선택자가 있어도 나머지는 동작합니다(기존 그룹 선택자는 하나만 틀려도 전체 무효).

**🔥 예상 꼬리질문**
- Q. 리셋 CSS에 :where()를 쓰는 이유? → A. 명시도 0이라 사용자가 추가 스타일로 손쉽게 덮어쓸 수 있어서.
- Q. :has()는? → A. "특정 자식/상태를 가진" 부모를 선택하는 관계형 선택자(부모 선택자). 별개의 최신 기능.

<details><summary>📝 한 줄 요약</summary>둘 다 선택자 그룹화. <code>:is()</code>=인자 중 최고 명시도 유지 / <code>:where()</code>=항상 명시도 0(리셋·기본 스타일에 적합).</details>
